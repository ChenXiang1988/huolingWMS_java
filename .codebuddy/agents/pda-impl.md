# 硬约束

1. **在线终端**：不做本地库、任务队列、同步引擎、端上规则快照；只保留超时重试、幂等与明确失败提示
2. **扫码按能力选通道，不按机型**：扫码头为主 / 摄像头为主 / 两条都是主路径，由设备能力声明决定；物理扫描键可绑定为触发键；**界面必须常驻屏幕扫码按钮**
3. **两条扫码通道都受服务端校验**：单条轻量接口，校验数据预热到缓存，连接复用（D25）
4. **执行片由服务端逐步生成**：界面只提交本次扫码数量，**不本地累加、不预估剩余量**，结案以服务端为准（06）
5. **反馈三通道同时给**：颜色 + 文字 + 声音；成功短音、失败长音或震动，均可关
6. **扫码失败就地回显**：在扫码框下方给具体原因，不弹整页错误、不跳页（与 `UI-F06` 同语义）；整页弹窗只用于危险操作（取消任务、报损）
7. **尺寸下限**：关键数字（数量、库位号、任务号、扫码结果）不小于 20 号，扫码结果不小于 24 号；主操作固定在屏幕下半部，滚动不离开视野
8. **接口只来自契约章**：路径、字段、错误码逐字对齐；生成的 Kotlin 模型不与契约冲突，**不手写同名字段绕过生成物**
9. **独立版本节奏**：接口向后兼容至少一版；不在本端做破坏性假设
10. **技术栈**：Kotlin + Android 原生，不引入跨端框架（Flutter / React Native 一类）与新的网络、依赖注入框架；需要新依赖先返回交主 agent 定
11. 不改 `openspec/`、`humandesign/` 文档，不改后端与 Web

# 工作方式

## 1. 先读后写

改一页之前先读该页现有多骨架、导航、扫码接入点与网络层。新页面沿用既有结构与命名，不新建第二套导航。

## 2. 顺序

按 `pda.md` 与 `12b` 的 `UI-M` 顺序推进：登录与设备能力声明 → 任务组 → 任务执行页 → 扫码区 → 提交与异常登记。每完成一块编一次。

## 3. 扫码接入

- 扫码头：按厂商 SDK 或广播接入，接入点集中在一个适配层，页面不直接调用厂商 API
- 摄像头：与扫码头走同一出口，页面只拿「扫码结果」一种事件
- 没有扫码能力时登录前拦截；摄像头不可用时允许手工录入并留痕

## 4. 网络出口

- 超时、重试、幂等键集中在网络层，页面不各写一套
- 断网或超时只给「失败 + 重试」，不给排队稍后提交一类的暗示
- 幂等键取值与契约章一致，不自行改窗口

## 5. 验证

- 先读工程既有 Gradle 任务名再跑；至少覆盖编译与静态检查（如 `assembleDebug`、`lint`，以工程实际任务为准）
- 扫码两条通道各验一遍：扫码头扫码与摄像头扫码；模拟器走 `10.0.2.2` 连本地 Site，真机走局域网地址
- 编译不过、静态检查新错误未清零，不许交付

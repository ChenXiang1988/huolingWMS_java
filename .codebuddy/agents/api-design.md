### 1.3 幂等约定

适用范围：所有写接口。读接口天然幂等，不要求幂等键，但不得有副作用。

| 项 | 契约必须定住 |
|---|---|
| 键的载体 | 统一 `Idempotency-Key` 请求头；单据类取外部单号，且必须与请求体外部单号一致，不一致按参数错误拒绝；非单据类取「任务号 + 动作 + 设备号 + 客户端请求号」；四个端同一规则（D21） |
| 键的格式 | 长度、字符集、大小写敏感、是否允许空格；服务端只做格式校验，不解析业务含义 |
| 键的作用域 | `货主 + 接口 + 键` 三元唯一；同一键在同一接口内只能对应一个请求指纹；跨货主同键互不影响 |
| 请求指纹 | 指纹覆盖方法、路径、查询参数、请求体；排除只影响传输、不影响语义的字段；契约只要求「同键同指纹才算重复」 |
| 首次与重复 | 首次返回正常结果或受理号；重复返回首次结果（同状态、同响应体），加 `replayed: true`；不新建单据、不重复扣减、不重复发事件 |
| 异步受理 | 异步接口的「首次结果」指首次受理响应（受理号 + 受理时间），不是执行结果；执行结果统一走查询或回调（D20） |
| 处理中 | 首次未完成时重复到达，返回 409（或 425，全章统一）+ `IDEMPOTENT_IN_PROGRESS` + `retryAfterMs`；调用方必须用原键重试 |
| 同键异体 | 同键但请求指纹不同，返回 `IDEMPOTENT_KEY_CONFLICT`，不覆盖首次结果；是否在错误体里返回首次结果摘要，全章统一一种做法 |
| 窗口 | 单据类随单据生命周期保留；执行类建议不少于 24 小时；窗口值以 `11` 为准，本章引用编号，不另写一套 |
| 状态存储 | 幂等记录必须持久化，进程重启与 Redis 故障不丢；记录键、请求指纹、首次响应、技术状态、过期时间；技术状态只用于去重，不进业务状态机、不对前端展示为单据状态 |
| 并发一致 | 同一键并发只产生一个业务结果；契约只承诺结果唯一与响应一致；去重手段（唯一约束 / 行锁 / 状态机守卫）归后端章 |
| 恢复 | 处理中必须有超时兜底：超过最长处理时间仍无结果，重复请求返回可重试失败或进入人工核对，不得永久卡在处理中 |
| 清理 | 清理不得早于业务唯一键失效；窗口过期后重复提交按新请求处理，但仍受业务唯一键与状态机约束，返回业务冲突而不是重复执行 |

幂等语义按操作类型固定，不逐接口自由发挥：

| 操作 | 幂等键 | 首次 | 重复 | 同键异体 | 对外承诺 |
|---|---|---|---|---|---|
| 创建单据 | 外部单号 | 202 + 受理号 | 202 + 同一受理号 + `replayed` | 409 | 只产生一张单据 |
| 更新单据 | 单号 + 版本号 | 200 | 200 + 当前状态 + `replayed` | 409 版本冲突 | 版本只前进一次 |
| 取消/删除 | 单号 + 动作 | 200/202 | 200 + 首次结果 + `replayed` | 409 | 只释放一次库存与锁定；数据不物理删除（INV-18） |
| 执行动作 | 任务号 + 动作 + 设备号 + 请求号 | 200 | 200 + 当前状态 + `replayed` | 409 | 同一动作只生效一次 |
| 查询 | 无 | 200 | 同结果 | — | 无副作用 |

以下写法直接判为未写完：只写「支持幂等」而不写键、作用域、窗口；异步接口重复提交返回执行结果而不是首次受理响应；同键异体覆盖首次结果；幂等记录只放 Redis；窗口过期后不再校验业务唯一键；处理中不设超时兜底。

### 1.4 错误码与统一错误响应

所有错误响应一个结构，不按端分叉：

```json
{
  "code": "STOCK_NOT_ENOUGH",
  "message": "可用库存不足",
  "traceId": "0af7651916cd43dd",
  "retryable": false,
  "retryAfterMs": null,
  "dataTimestamp": null,
  "details": [{"field": "qty", "reason": "超过可用量"}]
}
```

- `code` 是调用方唯一分支依据；`message` 只用于展示；`traceId` 用于报障与日志检索；`retryable` 由错误码决定，不由 HTTP 状态推断。
- 错误码命名 `域_原因`，大写常量，语义唯一，发布后不复用；禁止 `ERROR_001` 这类无语义编号。
- 本变更实际用到的错误码全章一张，列固定：错误码、HTTP 状态、类别、触发条件、可重试、调用方处置、出现位置（同步响应 / 异步查询 / 回调）。
- 每个错误码必须至少关联一个接口或一个回调事件；没有落点的错误码不写。
- 业务规则拒绝与状态冲突必须分开：前者改数据才能过，后者刷新后可能过。
- 异步受理后的失败不走 HTTP 错误，走查询结果或回调载荷，但错误码仍取自本表。

错误码表（本变更实际用到的码）：

| 错误码 | HTTP 状态 | 类别 | 触发条件 | 可重试 | 调用方处置 | 出现位置 |
|---|---|---|---|---|---|---|
| `PARAM_INVALID` | 400 | 请求不合法 | 字段缺失或越界 | 否 | 按字段提示修正 | 同步响应 |
| `IDEMPOTENT_IN_PROGRESS` | 409 | 幂等处理中 | 首次请求仍在处理 | 是 | 原键按 `retryAfterMs` 重试 | 同步响应 |

错误码类别与 HTTP 映射（固定，不逐变更改）：

| 类别 | HTTP | 错误码前缀 | 可重试 | 调用方处置 |
|---|---|---|---|---|
| 请求不合法 | 400 | `PARAM_` | 否 | 按字段提示修正 |
| 业务规则拒绝 | 422（若统一用 400，可合并，但错误码类别仍分开） | `RULE_` | 否 | 修正业务数据或转人工 |
| 未认证 | 401 | `AUTH_` | 否 | 重新登录或刷新令牌 |
| 无权限 | 403 | `FORBIDDEN_` | 否 | 换角色或申请权限 |
| 目标不存在 | 404 | `NOT_FOUND_` | 否 | 修正引用 |
| 状态/并发冲突 | 409 | `CONFLICT_`、`STATE_` | 刷新后可重试 | 重新查询最新状态再提交 |
| 幂等处理中 | 409 或 425 | `IDEMPOTENT_IN_PROGRESS` | 是 | 原键按 `retryAfterMs` 重试 |
| 限流 | 429 | `RATE_LIMITED` | 是 | 按 `Retry-After` 退避 |
| 依赖不可用 | 503 | `DEPENDENCY_` | 是 | 退避重试或走降级 |
| 系统错误 | 500 | `INTERNAL_` | 否 | 带 `traceId` 报障 |

## 2. 逐接口条目（每个接口一张表）

| 列 | 要求 |
|---|---|
| 编号与名称 | `API-001 收货单受理`，名称用业务动作，不用技术名 |
| 方法与路径 | 资源用复数名词；状态流转用子资源或显式 action |
| 端与角色 | 属于哪个端、哪些角色可调（对齐 05） |
| 鉴权 | token 类型 + 功能权限点 + 数据域注入规则（`owner_id` / 仓库域 / 设备绑定） |
| 请求（含边界） | 路径参数、查询参数、请求体：字段名、类型、必填、长度/精度/范围/枚举、示例；空值与缺省语义；批量上限；未知字段策略 |
| 响应（含降级） | 成功结构；异步接口返回受理号、查询入口与建议查询间隔；依赖不可用时的降级体与 `dataTimestamp`；查询走副本时标数据来源 |
| 错误码、超时与重试 | 本接口可能返回的错误码（只写码，不重复触发条件）；服务端超时预算；哪些可重试、最大次数、退避与 `Retry-After` |
| 限流 | 维度、阈值来源、超限错误码与 `Retry-After`；阈值本身由部署配置提供，不写死在契约 |
| 并发冲突 | 版本字段、冲突错误码、是否可重试；批量接口声明全成全败或逐条结果 |
| 幂等 | 是否幂等；幂等键来源（`Idempotency-Key`）与作用域、窗口；重复/处理中/同键异体的表现；引用 1.3 |
| 分页/排序/筛选 | 列表接口必填；只用键集分页 |
| 验收用例 | 首次、重复、并发重复（不少于 10 次）、同键异体；本接口每个错误码至少一个触发用例；降级与限流各一个 |
| 关联不变量 | 该接口守住哪条 INV，便于后端落强制手段 |

读接口可写「不适用（天然幂等／无并发写）」，但不能留空。

## 3. 回调与事件

| 项 | 必须定住 |
|---|---|
| 事件标识 | 每个事件一个全局唯一 `eventId`，重试不变；消费方按 `eventId` 幂等 |
| 订阅 | 订阅方式、可订阅事件清单、启停接口 |
| 载荷 | 事件类型、发生时间、业务单号、结果摘要、错误码（失败时）；不含内部实体与明细 |
| 签名 | 签名算法、签名头、时间戳、防重放窗口 |
| 重试 | 至少一次投递；退避序列、最大次数、超时；失败进死信并告警 |
| 消费方义务 | 先落库后处理；按 `eventId` 去重；失败返回非 2xx，成功返回 2xx；不得因重复投递产生二次业务结果 |
| 回调错误 | 失败事件也走统一错误码表，出现位置标「回调」 |

## 4. 契约验收（章末一张表，联调任务逐条引用）

| 验收项 | 可判定标准 |
|---|---|
| 完整性 | 100% 写接口有条目级幂等行；100% 接口有超时预算、错误码、限流维度、降级行为；无未登记的 `待确认` |
| 错误码 | 总表每行至少一个触发用例；所有 4xx/5xx 含 `code`、`message`、`traceId`、`retryable`；`retryable` 与类别一致；`message` 不含堆栈、SQL、内部地址 |
| 幂等 | 同一键并发不少于 10 次：单据 1 张、库存流水 1 条、领域事件 1 条、响应受理号一致；同键异体返回冲突且首次结果不变；处理中返回可重试错误 |
| 超时重试 | 注入依赖延迟超过预算：在预算内返回约定降级码，不产生半成品；按契约重试到上限，业务结果仍只有 1 份；非幂等接口自动重试的用例判失败 |
| 限流隔离 | 单货主超限只影响该货主该接口；外部流量打满时移动作业接口不受影响（D18） |
| 降级 | Redis、MQ、Hub、计费、下层关务物流分别不可用：按 `02` 矩阵返回；D19 查询降级带 `dataTimestamp`；库存真值不受影响 |
| 资源边界 | 批量超上限 1 行、分页超上限、超大请求体、深分页均在入口被拒，不进入业务逻辑 |
| 契约一致 | OpenAPI 生成物与契约章的字段、错误码、幂等键、超时预算一致；不一致即构建失败 |

# 阻塞处理

- 阻塞项 ≥3 条，或与 00 的决策 / 六条红线冲突 → **不落盘**，返回以 `STATUS: BLOCKED` 开头，先给阻塞清单
- 阻塞项 <3 条且不冲突 → 照常落盘，未定项在章内标 `待确认`，返回里单列
- 任何情况下都不许为了让文档看起来完整而假设业务规则

# 禁止事项

- 不写 SQL、表名、类名、字段存储细节（属后端设计）
- 不写页面、路由、组件、交互（属前端设计）
- 不替任何一端决定实现方式
- 不臆造未定的业务规则；缺失就写 `待确认` 并说明阻塞原因
- 不引入 `01-技术栈选型.md` 之外的技术或中间件
- 不改业务代码，不改 `00-决策字典.md`、`01-技术栈选型.md`

# 自检（交付前逐条过）

1. 每个写接口都有幂等键、作用域、窗口与重复提交行为
2. 每个接口的鉴权都同时写了功能权限与数据域
3. 每个接口都能追溯到一条 INV 或一条决策编号

8. 通用约定含 1.1 基础、1.2 鲁棒性、1.3 幂等、1.4 错误码表，四节齐全
9. 每个写接口有幂等键、作用域、窗口、重复/处理中/同键异体表现

12. 章末有契约验收表，每条能落到联调用例
13. 契约章没有出现表名、索引、锁、熔断器参数等实现手段

# 返回格式

6. **任务候选**：`tasks.md` 的联调任务，每条必须引用 `API-xxx` 编号；每个写接口至少一条重复提交用例，每个错误码至少一条触发用例

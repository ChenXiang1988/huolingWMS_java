# 审查清单

| 维度 | 查什么 | 判定 |
|---|---|---|
| 不变量覆盖 | 每条相关 INV 是否有 DB 层手段，还是全靠应用 | 有 INV 却既无 DB 手段也无说明 → 必改 |
| 禁止项 | VIRTUAL 枚举、可空 `location_id`、可空外键、用状态字段表达位置 | 出现即必改 |
| 唯一键与空值 | 六字段唯一键是否完整；`serial_no` 策略在文档内是否前后一致；部分索引条件与软删除列是否对齐 | 不一致 → 必改 |
| CHECK 完整 | `qty_allocated <= qty_on_hand`、数量非负、枚举封闭 | 缺失 → 必改 |
| 索引 | 每条索引背后有没有具体查询；外键列是否建索引；是否有重复前缀；复合索引顺序 | 冗余或无支撑 → 建议改 |
| 迁移安全 | NOT NULL 是否走三步回填；是否改了历史脚本；是否可重复执行；锁表时长是否有估计 | 违反 → 必改 |
| 精度与单位 | numeric 精度是否够、换算单位是否落库、有无 float | 有问题 → 建议改 |
| 时间与日切 | `timestamptz`、UTC 存储、日切口径 | 缺失 → 建议改 |
| 数据归属 | 表是否落在权威源一侧（Hub 权威 vs Site 权威） | 放错库 → 必改 |
| 数据量假设 | 流水、任务这类只增不减的表，有没有归档或分区考虑 | 没有 → 建议改 |

# 输出

只在对话里返回清单，不写文件。按三档排：

- **必改**：会破坏不变量或让迁移失败。每条给：位置、违反的 INV 或决策编号、怎么改（一两句）

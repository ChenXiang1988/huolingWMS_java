# 硬约束

1. `wms-kernel` 不依赖 Spring，**不变量只允许在 kernel 定义**；Hub / Site / Open 只能调用，不得各写一套校验
2. 三个 bootable 单元不得互相依赖，只允许单向依赖 kernel 与 common
3. 库存、库位、分配强一致：单库事务 + 行锁，同事务完成，**不用分布式事务、不用 Seata**
4. 禁止虚拟库位；`location_id NOT NULL` + FK；库存状态与物理位置正交（D26、D27）
5. 库存唯一键六字段 `(owner_id, location_id, sku_id, batch_no, stock_status, serial_no)`，`serial_no NOT NULL DEFAULT ''`（D29）
6. 货主是唯一隔离维度，查询强制注入 `owner_id`，代码禁止 `isInternal` / `ownerType == INTERNAL`（D02、D03）
7. 表结构变更只能通过 Flyway，**历史脚本不可修改，只能新增**
8. 禁止引入 Spring Cloud 组件与 `01-技术栈选型.md` 之外的技术
9. 跨境关务与物流段不归 WMS，只消费下层服务返回的结果摘要（00 第 11 节）
10. 不改业务代码，不改 `00-决策字典.md`、`01-技术栈选型.md`

## 数据模型与 DDL（本变更最硬的一节）

判定标准很低：表结构要能被 DBA 直接拿去开 Flyway 脚本，每条约束要能追到 INV 编号。建模口径以 00 第 7 节与 D26–D31 为准，逐项满足：

| 项 | 要求 | 依据 |
|---|---|---|
| 表清单 | 表名 / 用途 / 权威源（Hub 或 Site）/ 新增或变更 / 脚本编号；表落在错误的库即违规 | D12 |
| 字段 | 类型、非空、默认值、枚举取值、单位；数量与重量用 numeric 给精度，不许 float | — |
| 货主键 | 所有业务表 `owner_id` 非空 | INV-06 |
| 库位键 | `location_id NOT NULL` + FK；枚举不含 VIRTUAL | INV-01 |
| 库存唯一键 | `(owner_id, location_id, sku_id, batch_no, stock_status, serial_no)` | D29 |
| serial_no 空值 | 二选一并写明理由：部分唯一索引排除空值，或 `NOT NULL DEFAULT ''`。**现行文档不一致**：01 选前者、D29 选后者，本次必须定死一条并登记冲突 | 01 / D29 |
| CHECK 约束 | `qty_allocated <= qty_on_hand`、数量非负、状态枚举封闭 | INV-08 |
| 软删除 | 数据不物理删除；唯一键与部分索引的条件必须与软删除列一致，否则删掉后无法重建同键记录 | INV-18 |
| 索引 | 每条索引对应一条具体查询；外键列必须有索引；复合索引等值列在前、范围列在后；不写无查询支撑的索引 | — |
| 时间 | `timestamptz` 存 UTC；按日计费、日结的日切口径单独说明 | D38 |
| 迁移与回填 | 新增 NOT NULL 列走三步：加可空列 → 分批回填 → 加约束，每步一个脚本编号；写明锁表时长与回滚方式 | — |
| 脚本纪律 | 只新增、不改历史脚本、可重复执行 | 01 |

写完这一节前自己对一遍：表清单齐了没、每条约束有没有挂 INV、索引背后有没有查询、回填是不是分了三步、serial_no 策略定了没。缺一项就别交。

写法要求：

- 三条及以上并列要素用表格
- 每条规则写明强制手段（DB 约束 / 应用校验 / 定时核对）
- 引用决策与不变量写编号（`见 00 D29`、`见 INV-08`），不复制原文
- 允许表结构 DDL 片段与领域行为表；不写 Controller / Service 类清单式的伪代码

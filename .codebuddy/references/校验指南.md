# 设计文档校验指南

本文件是参考资料，按需查阅。`design.md` 写完不算完成，必须过校验脚本。脚本能查的不用人眼，人眼只查脚本查不到的。

## 一、命令

```bash
# 收口前必跑（自动定位 openspec/changes 下唯一未归档变更）
python3 .codebuddy/tools/check-design.py

# 指定变更
python3 .codebuddy/tools/check-design.py <变更名>

# 建变更目录时生成三段骨架
python3 .codebuddy/tools/check-design.py --init <变更名>

# 只校验 12 / 12a / 12b 界面与移动作业端规范
python3 .codebuddy/tools/check-design.py --only norms

# 只校验变更三章
python3 .codebuddy/tools/check-design.py --only design

# 机器可读，供后续自动化
python3 .codebuddy/tools/check-design.py --json

# 严格模式：WARN 也算失败
python3 .codebuddy/tools/check-design.py --strict

# 查检查项与格式依赖
python3 .codebuddy/tools/check-design.py --list-checks
```

退出码：`0` 通过；`1` 有 ERROR（`--strict` 下 WARN 也算）；`2` 无法定位检查对象。

## 二、什么时候跑

| 时机 | 目的 |
|---|---|
| 变更目录建好后 | 确认骨架完整、未被误改 |
| 每个子代理返回后 | 抓该章刚写出来的问题，趁上下文还热 |
| 三章收口前 | 必须 ERROR 为 0 才能交给实现 |
| `ui-design` / `pda-design` 返回后 | 查 12 / 12a / 12b 的 `UI-*` 与 `UI-M` 编号闭合及必备条目 |
| `openspec-apply` 前 | 防止收口后又被改坏 |

不允许「等代码写完再一起验」：设计阶段的问题到实现阶段才暴露，返工成本高一个量级。

## 三、格式契约（脚本依赖，不可随意改）

1. 三个二级标题，顺序固定：`## 前端设计`、`## 后端设计`、`## API 接口契约`。
2. 每个接口一个三级标题：`### API-001 动作名`，编号三位、全局唯一、不复用。
3. 表清单表头含「表名」，且有一列含「脚本」，单元格写 `V001__xxx.sql`。
4. 页面映射表表头同时含「页面」与「接口编号」。
5. 业务错误码用大写常量（如 `STOCK_NOT_ENOUGH`）。用了才能自动对账，用中文则降级为人工核对。错误码表必须同时含「错误码」「HTTP」「重试」「触发条件」「出现位置」列；写接口条目的幂等行必须含键、作用域、窗口、重复/处理中、同键异体。
6. 引用的 `INV-xx` 与 `Dxx` 必须在 `00-决策字典.md` 中真实存在，不得自造编号。

规范文档（12、12a、12b 界面与作业规范）另有三条：

7. 四段骨架齐全：`## 结论`、`## 问题`、`## 设计`、`## 约束与验证`。
8. 条目编号两位数字，定义行必须以编号开头：表格首列 `| UI-I01 |`、加粗 `**UI-I11 …**`、或标题 `### UI-M01`。只出现在句中算引用，必须能追到定义行。
9. 十六进制色值只允许出现在 `UI-Txx` 令牌条目所在行；移动作业端规范不得出现「离线可用 / 稍后同步 / 断网继续 / 本地缓存」。

改这些格式等于改契约，必须同步改脚本，并在本次变更中登记改动原因。

## 四、结果处置

| 级别 | 处置 |
|---|---|
| ERROR | 必须改文档。不得改脚本、删检查项、调正则来「通过」 |
| WARN | 改；或确认属于合理例外，在收口说明里逐条写理由 |
| INFO | 仅提示降级或跳过，不需处理 |

硬禁止：为了让检查变绿而把章节写成空话、把 `待确认` 换成编造的答案、删掉 `关联不变量` 列。检查器拦的是格式，拦不住糊弄；这两件事要一起管。

**已知遗留项**：当前版 12、12a、12b 已落盘。运行 `--only norms` 若仍报 `NORM-04`、`NORM-06`、`NORM-07`，根因是脚本的「必备编号与色值」契约与 12 / 12a 的分工不一致（页面骨架定义归 12a，脚本仍要求在 12 内定义）。这是归档版沿袭的契约缺陷，已登记当前版 `23-权威源与引用矩阵.md` 待定项；不得删检查项、改 `optional` 或调正则来让检查变绿，须作为独立变更修订契约并登记原因。版本门禁见 `.codebuddy/rules/version-policy/RULE.mdc`。

### 窄范围变更豁免

纯呈现层与工具类变更没有接口、没有表结构，`API-01` 一类结构性检查对它不成立。校验器按文档内容识别这类变更，满足三条才豁免：

1. 契约章没有任何 `### API-xxx` 接口条目；
2. 契约章含声明「本次无接口变更」；
3. 后端设计章含声明「本次无表结构变更」。

缺一条就不豁免，宁可误报。豁免范围只有九项：`API-01`、`BE-03`、`BE-04`、`BE-05`、`BE-06`、`BE-07`、`FE-03`、`FE-04`、`FE-05`；每项在输出里以 INFO 逐条登记，不进 WARN 与 ERROR 统计。

不豁免：三章结构、`INV` 与 `D` 编号闭合、禁用词、错误码表、鲁棒性与幂等三节、五类页面状态（`FE-06`）、页面与接口映射、tasks 联调引用闭合、版本门禁。

两条使用纪律：

- 声明是判定依据，不是免罪符。真写了接口就必须给接口条目，否则 `API-01` 仍报；「无接口变更」只写给确实没有新接口的变更。
- 豁免不等于内容可以省。窄范围变更照样要写契约验收、五类页面状态与适用性说明，缺了照旧报错。

## 五、检查项分组

脚本 `--list-checks` 是权威清单，此处只列分组：

| 组 | 查什么 | 对账依据 |
|---|---|---|
| 结构 | 三章齐全、顺序正确、无占位残留、标题层级一致 | `openspec/config.yaml` |
| 编号 | API 编号唯一连续、引用闭合；INV / D 编号在 00 中真实存在 | `00-决策字典.md` |
| 禁用项 | VIRTUAL、内部货主分支、微服务组件、浮点数量、契约写表名、前端写 SQL | 00 第 7 节与 D02、D09、D26 |
| 特征词 | 受理号（D20）、数据时间戳（D19）、幂等键（D21）、六字段唯一键（D29）、CHECK（INV-08） | 00 决策编号 |
| 鲁棒性与幂等 | 契约章是否含鲁棒性、幂等约定、契约验收；写接口幂等要素；错误码表列；接口条目的超时、限流、降级、并发、验收 | `api-design` 通用约定与 D21 |
| 跨章对账 | 页面映射、联调任务、错误码、接口落点、不变量手段的引用闭合 | 契约章为唯一源 |
| 规范文档 | 12 / 12a / 12b 的四段骨架、`UI-*` / `UI-M` 编号定义唯一与引用闭合、范围覆盖、必备条目、色值约束、离线禁用词、index 登记、`pda.md` 变更差异引用闭合 | 12 号自身编号体系、`pda-design` 定义、D16 |
| 版本门禁 | 产物不得引用非当前版本路径；确需溯源须标注并降级为警告 | `current-version.txt`、`.codebuddy/rules/version-policy/RULE.mdc` |

## 六、局限（必须说清）

这是**文档级一致性检查**，它证明不了实现正确：

- 查不出业务规则本身设计错了。规则错，写得再规范也错。
- 查不出并发方案在实际压力下是否成立。
- 查不出超时预算是否合理、幂等窗口是否够长，只能查是否成节、是否写了要素。
- `kernel` 不依赖 Spring、三个 bootable 单元互不依赖这类架构约束，脚本只能看文字，跑不了 ArchUnit。

等父 POM 与四个 module 建起来后，分层由 ArchUnit 断言、不变量由集成测试断言，脚本退回只管文档。两者的分工不能互相替代。

## 七、资料分工

| 资料来源 | 管什么 |
|---|---|
| `openspec/config.yaml` | 三章结构与章节硬性内容要求 |
| `.codebuddy/agents/*.md` | 每个子代理的写作标准与自检清单 |
| `.codebuddy/rules/version-policy/RULE.mdc` | 当前有效版本指针、归档版本只读禁令、过渡期回查规则 |
| `humandesign/sysdesign/current-version.txt` | 机器可读的当前版本指针，脚本从此解析目录 |
| `.codebuddy/references/校验指南.md` | 校验的执行时机、格式契约、结果处置 |
| `humandesign/sysdesign/<当前版>/00-决策字典.md` | 决策与编号的权威源，冲突时以它为准 |
| `humandesign/sysdesign/<当前版>/00a-红线与不变量.md` | 红线与不变量的权威源 |

子代理的自检是自查，脚本是复查，两者都要跑：自查会漏，复查不认自述。

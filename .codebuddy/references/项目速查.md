本文件是参考资料，按需查阅，**不是行为约束**。约束本身见 `.codebuddy/rules/` 下四份「总是加载」的规则。凡与本文件冲突，以对应约束规则为准。

## 二、一次变更的四类产物

提案、增量规格、设计、任务清单四类齐全，设计按 `openspec/config.yaml` 写三章；规范文档引用 `<当前版>` 路径，不写具体版本号。

| 产物 | 文件 | 要点 |
|---|---|---|
| 提案 | `proposal.md` | 为什么做、边界在哪 |
| 增量规格 | `specs/**/spec.md` | 需求 delta 是源头，proposal 只是摘要 |
| 设计 | `design.md` | 前端设计 / 后端设计 / API 接口契约三章 |
| 任务清单 | `tasks.md` | 可独立交付的任务，验收方式写清 |

界面与交互差异写 `ui.md`，移动作业端差异写 `pda.md`；校验记录与实测证据写 `verification.md`。

## 三、分派对应表

| 改动对象 | 承接子代理 | 前置条件 |
|---|---|---|
| 后端源码、Flyway、后端配置 | `backend-impl` | 接口契约章与后端章已收口 |
| Web 三端页面与前端工程 | `web-impl` | 前端章已收口，接口只调契约既有条目 |
| 安卓端 | `pda-impl` | 移动作业端规格已收口 |
| 测试代码与测试矩阵 | `test-author` | 被实现的代码已落盘 |
| 工具脚本与校验脚本 | 无专用代理 | 主代理出方案，向用户申请派发或授权例外，并在交付说明登记 |
| 只读审查，不改代码 | `code-review`、`db-review` | 实现与测试完成之后 |

设计段串行顺序：接口契约 → 后端设计 → 界面与交互 → 前端设计 → 移动作业端 → 表结构审查；前三者写同一份 `design.md`，必须串行。实现段在目录不重叠时可并行。

## 四、常用命令

| 用途 | 命令 |
|---|---|
| 盘点未归档变更 | `openspec list --json` |
| 设计文档校验 | `python3 .codebuddy/tools/check-design.py` |
| 分派门禁校验 | `python3 .codebuddy/tools/check-agent-dispatch.py` |
| 仓型判定落点扫描 | `bash code/backend/scripts/check-warehouse-type.sh` |
| 后端全量构建 | `mvn -f code/backend/pom.xml clean verify`（需 JDK 21，显式设 `JAVA_HOME`） |
| 后端定向测试 | `mvn -f code/backend/pom.xml -pl <改动模块> -am test` |
| 前端类型检查与构建 | `pnpm typecheck && pnpm build` |
| 前端启动 | `cd code/web && pnpm dev` |
| 本地中间件状态 | `docker compose -f code/deploy/local/compose.yaml ps` |
| 本地中间件启动 | `docker compose -f code/deploy/local/compose.yaml up -d <服务名>` |
| 本地中间件收尾 | `docker compose -f code/deploy/local/compose.yaml down` |

前端没有测试脚本，根 `package.json` 只有 `dev`／`build`／`typecheck`，不要把 `pnpm test` 写进任务清单；规格校验也不叫 `pnpm spec:validate`。

## 五、校验脚本的已知事项

- `check-design.py` 的规范清单按当前版登记名对齐：共享底座读 `12-界面与交互设计规范.md`，页面骨架读 `12a-网页页面与分端规格.md`，移动作业端读 `12b-移动作业端规格.md`；界面编号统一为 `UI-*`，移动作业端占 `UI-M` 段。
- `13-pda-interaction-design.md` 与 `PDA-*` 前缀是废弃口径，任何文件不得再沿用。
- 规范文件缺位期间 `--only norms` 会报 `NORM-01`，这是已知待迁入项，不是校验器故障；不得删检查项、改 `optional` 或调正则来让检查变绿。
- `check-design.py` 只做文档级一致性检查，证明不了实现正确；分层由架构断言、不变量由集成测试负责。

## 六、本地开发与端口口径

行为约束见 `.codebuddy/rules/dev-lifecycle/RULE.mdc`；本节只列查阅口径。

| 类别 | 端口或名称 | 说明 |
|---|---|---|
| 容器编排 | `huoling-wms-local` | `code/deploy/local/compose.yaml` 的项目名，只管理本地中间件 |
| 本地中间件 | `5433`、`6379`、`5672`、`15672` | 分别对应 PostgreSQL、Redis、RabbitMQ 与 RabbitMQ 管理页 |

| 应用服务 | `8082`、`8083`、`8094` | 当前前端代理使用的应用服务端口 |
| 旧端口 | `8092`、`8093` | 当前代码未引用，不再作为新启动端口 |

查重按当前项目工作目录、编排项目名、启动命令和端口交叉判断；清理只限当前项目登记项。端口被其他项目占用时，只登记冲突，不清其他项目进程。

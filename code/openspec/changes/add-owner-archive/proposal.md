# Proposal

## Why

当前有效版本已经把货主档案登记为主数据的一部分，但代码里没有落地，形成三处断口：

- `11-技术落地.md` 第 218 行把 `wms_owner` 列入主数据表清单，实际迁移脚本里没有这张表。
- `24-分端功能清单.md` 第 3.3 节登记了运营端「货主建档、改档、停用」，`05-角色与权限矩阵.md` 也把「建货主档案」写进主数据管理员的职责，运营端页面与后端接口都不存在。
- 货主标识目前只是一个没有外键约束的 `owner_id`，挂在 `wms_account` 与 `hub_sku_archive` 上；运营端货主选择器（API-020）只能从货主端账号反向派生展示名，`OwnerDirectoryPO` 的注释已自述「当前有效版本没有货主档案表」，并把它标为契约缺口。

后果是连锁的：货主端账号开不出来（账号页没有货主可选），商品档案的归属货主是凭空数字，合同与账单的归属对象缺位，`25-分端操作场景.md` 场正-01「货主开通」整条场景跑不通。这是货主端全部功能的前置，不能靠下游绕开。

## What Changes

- 建立货主档案主数据：新增 `wms_owner` 表，含全局唯一的货主编号、展示名、状态与审计列；状态只表达主数据可用性，不用来表达合同是否生效（`D33` 无生效合同不可作业仍归计费域判定）。
- 运营端获得货主档案的查询、建档、改档、停用与重新启用能力，入口按 `24` 已登记的「货主建档、改档、停用」落成页面，页面骨架取 `UI-P01` 与 `UI-P03`。
- **BREAKING** 替换货主选择器的数据来源：API-020 由「从货主端账号派生」改为读真实货主档案，关闭该契约缺口；货主编号成为选择器与代建页的可查字段。
- **BREAKING** 为货主标识补上主数据约束：`wms_account.owner_id` 与 `hub_sku_archive.owner_id` 建立指向 `wms_owner` 的引用完整性，存量裸数字按迁移脚本回填后才允许加约束。
- 货主账号开通增加前置校验：货主端账号必须绑定一个存在的货主档案，绑定后货主不可变更；货主停用后其名下账号一律拒绝登录，数据保留在库。
- 停用口径照 `25` 场逆-01：停用阻断新建业务，不阻断存量单据与任务走完；停用不自动恢复，重新启用必须由人操作并留痕。单仓端按货主状态下行副本判定，副本无记录或超过 1 小时未更新且 Hub 不可达时一律拒绝，不放行可能已停用的货主。
- 同步修订设计文档：`11`（表清单落地）、`21`（新增货主档案状态枚举）、`22`（新增货主档案状态机行）、`05`（货主档案权限点与角色矩阵）、`24`（补齐权限点模块与角色），并记入 `log.md`。
- 明确不纳入本次范围：合同与费率卡的绑定（计费域 `wms-billing` 仍是空壳，另立变更）、货主端其余五项功能、仓级授权（`D40` 不走仓级授权）、开放接口建货主、货主自助注册。

## Capabilities

### New Capabilities

- `owner-archive`: 货主档案主数据的生命周期，包含编号与命名规则、字段分层、可用与停用两态、停用对存量业务的边界，以及货主账号与货主档案的绑定约束。

### Modified Capabilities

无。

## Impact

- 数据库：新增 `wms_owner` 迁移；`wms_account` 与 `hub_sku_archive` 补外键约束，需要先回填存量 `owner_id`，回填规则由设计章定。
- 后端：`code/backend/wms-hub` 新增货主档案领域对象、服务、接口与权限点；改造 `OwnerSelectorService` 与 `OwnerDirectoryPO`，删除从账号派生的投影。
- 契约：`code/contracts/openapi.json` 新增货主档案接口，`/api/hub/owners` 的响应语义变更；三端生成的类型需同步再生。
- 前端：运营端新增货主档案列表与表单页、菜单与权限点；账号页在开通货主端账号时增加货主选择。
- 设计文档：当前有效版本的 `05`、`11`、`21`、`22`、`24` 需修订，`18-上线与数据迁移.md` 的「货主档案导入」在本次获得可执行的导入对象。
- 权限点：新增货主档案读写权限点并写入初始化脚本，绑定主数据管理员；运营端其他角色只读。
- 风险：`owner_id` 回填是本次唯一的存量数据风险点，回填不完整会导致外键创建失败，须在迁移脚本内先校验再建约束。
- 存量回填成本：现有货主标识只能从账号反推一个展示名，信用代码、联系人、联系电话都没有来源，回填必须人工补录后再建约束；`18-上线与数据迁移.md` 的「货主档案导入」清单需按四必填调整。回填分两个发布批次，建表与补录先上，外键单独一批，待补录清单清零、运营确认的不保留历史货主处置完毕后才执行。

## 已定口径（2026-11-25）

以下三项业务口径已拍板，设计与契约按此执行，不再作为待确认：

| 项 | 结论 |
|---|---|
| 停用后的货主账号 | 一律拒绝登录；历史数据保留在库，存量单据与任务照旧走完 |
| 货主档案必填字段 | 名称、联系人、联系电话、统一社会信用代码四项 |
| 货主展示名唯一性 | 不要求全局唯一，允许同名主体，靠货主编号区分 |

由必填推导的一条附加约束：统一社会信用代码作为法人唯一标识，按全局唯一校验；若与业务预期不符，在契约定稿前提出。

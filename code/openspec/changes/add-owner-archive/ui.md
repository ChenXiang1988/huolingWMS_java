# 本次界面与交互差异

本文件只写 `add-owner-archive` 在运营端 Web 上的界面与交互差异：货主档案的查询、建档、改档、停用与启用，账号页开通货主端账号时选择货主，以及受理票据与版本冲突的表达。共享规则一律按编号引用 `12-界面与交互设计规范.md` 与 `12a-网页页面与分端规格.md`，本文件不复制其正文。

`OA-01`~`OA-10` 是本变更内部的差异条目号，供 `tasks.md` 与后续前端设计章引用；`UI-*` 编号一律指向常驻规范，`OA-*` 不进入 `UI-` 序列，也不在 `12`、`12a` 登记。

不覆盖：路由、菜单与权限点编码、页面到接口的字段映射（归前端设计章）；货主端与单仓端界面；接口契约与后端实现。

### 1.2 OA-01 货主档案列表查询与翻页

- **触发**：进入货主档案列表页。页面归 `UI-P01`：页头（标题「货主档案」+ 主操作「新建」）→ 筛选区 → 表格 → 分页，顺序固定。
- **动线**：筛选区输入条件 → 「查询」→ 表格出现结果 → 「上一页 / 下一页」翻页 → 点行进入 OA-02。条件、排序与游标位置写入地址栏（`UI-X04`），从详情返回时按 `UI-X10` 还原。
- **筛选构成**：常显 4 项（`UI-C02` 一行最多 4 项）——货主编号（精确，控件宽 160）、货主名称（模糊，控件宽 200）、状态（可用 / 停用，控件宽 140）、更新时间范围（控件宽 360，快捷项为今天 / 近 7 天 / 近 30 天，`UI-C12`）；第 5 项「信用代码」（精确，控件宽 200）折叠在「展开」内，折叠状态随地址栏保留。排序不占筛选位，用表头三列（货主编号、货主名称、更新时间）点击切换升降序，白名单外的列不给排序图标。
- **分页**：游标式，只有「上一页 / 下一页」与「每页 20 / 50 / 100」；**不显示总条数与总页数**（契约不返回总数，不得伪造）。改每页条数、改排序、改筛选任一动作都重置游标回第 1 页，并清空「上一页」栈（`UI-I09`）。
- **表格列与宽度**：货主编号 160（按 `UI-B08` 展示件：完整不截断、可复制、超宽中间省略并悬浮全号）、货主名称 min 200、联系人 120、联系电话 140、信用代码 200、状态 110（`UI-C06` 圆点 + 文字，固定在同一列）、更新时间 160（列表档 `UI-W13`）、操作 90（固定右侧）。列表不显示版本号，版本号只在详情抽屉出现。
- **界面状态**：默认——首屏 20 行，无选中，筛选为空；加载——首次进入超 300ms 用骨架屏（`UI-S01`、`UI-C24`），翻页与查询用表格内 loading，不重绘骨架；空——`UI-S02`，无任何档案时主文案「暂无货主档案」、次文案「尚未建立任何货主档案」、出口「新建」，筛选过窄时主文案「暂无数据」、次文案「当前筛选条件下没有记录」、出口「重置」；失败——`UI-S04` 区域内错误块，筛选与游标保留，出口「重试」；无权限——无功能权限时入口不渲染（`UI-X06`），持读权限但数据域为空（`FORBIDDEN_OWNER`）或直接访问路由时按 `UI-S03` 整页「无权访问」并写明需联系权限管理员。
- **文案口径**：动作词只用词表（`UI-W01`）——「新建」「查询」「重置」「详情」「上一页」「下一页」；不写「新增」「搜索」「加载更多」。空态三段按 `UI-W10`。错误按 `UI-W07` 三段并附错误码自后（`UI-S06`）。列表不出现合同、费率与仓库字段（`D33`：状态不表达合同；`D40`：不做仓级授权，故不提供按仓库筛选）。
- **恢复路径**：任何失败都可「重试」；空态可「新建」或「重置」；403 可返回上一页。
- **引用与新增**：复用 `UI-P01`、`UI-C01`、`UI-C02`、`UI-C08`、`UI-S01`~`UI-S04`；本次新增的是三个排序白名单列、四项筛选与游标式分页控件（见第 3 节待确认第 1 条）。

### 1.3 OA-02 打开货主档案详情抽屉

- **触发**：表格行点击、货主编号点击、行内「详情」按钮，三者行为一致，在当前页打开右侧抽屉（`UI-D01`），不跳独立详情路由。
- **动线**：打开抽屉 → 抽屉加载详情 → 点左侧分段目录或滚动正文（`UI-D03` 双向联动）→ 底部操作：编辑（OA-04）、停用（OA-05）或启用（OA-06）→ 关闭抽屉回列表原位。
- **主成分区与字段**：三个分区，顺序固定（`UI-D05`，无「进度与数量」「明细」分区，跳过不重排）——基础信息：货主编号、货主名称、联系人、联系电话、信用代码、状态、版本；状态变更：动作（建档 / 停用 / 启用）、原因、操作人、变更时间（到秒即用详情档，`UI-W13`）；操作记录：创建人、创建时间、最后修改人、最后修改时间（`UI-B09`，未修改过时只显示创建信息）。
- **界面状态**：默认——头部四件套齐全，左目录三段落高亮第一段；加载——超 300ms 用骨架屏（`UI-S01`、`UI-D11`），不整层白屏；空——某分区无数据时给一句说明不隐藏分区（`UI-D11`）；失败——分区内错误块 + 重试（`UI-S04`、`UI-D11`）；无权限——目标不在数据域时按不存在处理，抽屉内显示 `UI-S04` 错误块「货主档案不存在或不在你的数据域内（NOT_FOUND_OWNER）」+「关闭」出口（`UI-D11`）。
- **文案口径**：标题为货主名称；副标题为「货主编号 OW000123」，不重复状态词（`UI-D06`）；状态标签文字只用「可用」「停用」。
- **恢复路径**：失败可「重试」；404 与 403 可「关闭」返回列表，列表上下文不丢（`UI-D08`）。
- **引用与新增**：外壳、字段皮肤、导航与联动、关闭出口全部复用 `UI-C04`、`UI-D01`~`UI-D13`；本次只传数据与三段落，不新增外壳，具体传参见 2.2。契约只返回最近一次状态变更，故不使用时间线（`UI-C17` 不适用）。

### 1.4 OA-03 新建货主档案

- **触发**：列表页页头「新建」。无写权限时该按钮不渲染（`UI-X06`，不置灰）；数据域为「指定列表」时账号本不能建档，按钮也不渲染并给一句说明。
- **动线**：进入表单页（`UI-P03`：页头「新建货主档案」→ 单组表单「货主信息」→ 底部固定操作条）→ 填四项 → 提交 → 202 受理票据（`UI-I12`）→ 表单转只读并进入受理中（OA-09）→ 轮询结果 → 成功给结果与下一步，失败恢复可编辑。
- **表单字段与规格**：货主名称（必填，1~128 字，标签宽 100）、联系人（必填，1~64 字，标签宽 100）、联系电话（必填，6~32 位，允许数字、空格与 `+ - ( )`，标签宽 100）、信用代码（必填，18 位大写，标签宽 100）。控件高 32、纵向间距 16、段内单列、标签右对齐（`UI-C03`）。表单**不出现**货主编号、状态、版本、仓库、合同字段——前三个由服务端生成（契约不接受传入），后两个不属本对象。
- **帮助文案**：信用代码控件下方 4px 辅助色写「统一社会信用代码，固定 18 位大写字母与数字，不含字母 I、O、S、V、Z」（不校验校验位，故不提示「校验位」）；货主名称下方写「允许重名，同名以货主编号区分」；联系电话下方写「6 至 32 位，可含空格与 + - ( )」。帮助文案字号 12、辅助色（`UI-C03`）。
- **校验时机与口径**：失焦做字段级校验，提交做整体校验；错误在控件下方 4px、危险色（`UI-C03`），文案只说规则（`UI-W09`）——「必填」「最多 128 个字」「需为 18 位大写字母与数字」。**不做前端查重、不弹「名称已存在」**：名称允许重复是既定口径，任何本地去重提示都会误导。信用代码的重复判定只在受理结果里出现（`RULE_DUPLICATE_CREDIT_CODE`，见 OA-10）。
- **必填与置灰的分界**：字段级必填缺失不置灰提交按钮，点提交后就地提示并聚焦第一个错误字段；置灰只用于操作前置（`UI-I03`）——无写权限、数据域非全域、详情未加载完成、受理中。
- **界面状态**：默认——四项为空、提交可点；加载——详情不适用，提交中用按钮行内 spinner，控件尺寸不变（`UI-I05`、`UI-C27`）；空——不适用；失败——同步错误就地定位字段（`PARAM_INVALID` 按 `details[].field`），受理失败在表单顶部错误块给三段文案与出口（OA-10）；无权限——按 `UI-S03`。
- **文案口径**：主按钮「提交」、次按钮「取消」（`UI-W01`）；成功提示说结果不说过程（`UI-W11`）——「货主档案已建档，货主编号 OW000123」。
- **恢复路径**：失败保留原输入并可「重新提交」（`UI-F03`）；离开前有未保存内容时提示（`UI-I07`），返回后恢复已填四项；成功给「查看详情」（按受理结果的货主编号定位到列表该行并打开抽屉）与「返回列表」两个出口。
- **引用与新增**：复用 `UI-P03`、`UI-C03`、`UI-C07`、`UI-I05`、`UI-I07`、`UI-I12`、`UI-W09`、`UI-W11`；本次新增的是四项字段的文案与「名称允许重名」的提示口径。

### 1.5 OA-04 编辑货主档案

- **触发**：详情抽屉底部「编辑」。档案为停用态时该按钮**置灰**并在按钮左侧给一句原因「停用状态不可改档，需先启用」（`UI-I03`）；无写权限时按钮不渲染（`UI-X06`）。
- **动线**：点「编辑」→ 详情抽屉关闭（`UI-D09` 抽屉内不套抽屉）→ 打开表单页「编辑货主档案」→ 按详情接口取最新数据回填四项与版本 → 修改 → 提交 → 202 → 受理中（OA-09）→ 结果。
- **与新建的差异**：页头副标题显示只读的「货主编号 OW000123」，不作为可编辑字段（编号不可变，契约不接受传入）；提交时携带进入表单时取到的版本号；状态与版本不作为表单字段展示。表单页标题写「编辑货主档案」，不写「修改」（`UI-W01`）。
- **中断恢复**：离开未保存表单前提示（`UI-I07`）；恢复时**只还原四项输入，版本号每次进入表单重新取**——缓存旧版本号会让恢复后的第一次提交必然撞版本冲突。
- **界面状态**：默认——按最新详情回填；加载——首次取详情超 300ms 骨架屏（`UI-S01`），失败用 `UI-S04` 错误块 + 重试；空——不适用；失败——同步与受理失败按 OA-10 分派；无权限——`UI-S03`；深链接进入但档案已停用时，页面顶部给警告条「该货主已停用，需先启用后再改档」，提交按钮置灰并给同一原因。
- **文案口径**：主按钮「提交」，次按钮「取消」；成功后提示「货主档案已更新，货主编号 OW000123」（版本递增由详情体现，不在提示里喊「版本 +1」）。
- **恢复路径**：失败保留输入；版本冲突走 OA-10 的两个出口；成功后回列表并按 `UI-X10` 还原筛选与游标。
- **引用与新增**：复用 `UI-P03`、`UI-D08`、`UI-D09`、`UI-I07`、`UI-X10`、`UI-X12`；本次新增的是「停用态置灰并给原因」与「恢复草稿不恢复版本号」两条。

### 1.6 OA-05 停用货主档案

- **触发**：详情抽屉底部「停用」（档案为可用态）。无写权限时按钮不渲染（`UI-X06`）。
- **动线（含两次确认）**：抽屉底部点「停用」（第一次确认意图）→ 抽屉关闭 → 弹窗 `UI-C05`（宽 480）→ 必填停用原因 → 点弹窗主按钮「停用」（第二次确认）→ 202 → 弹窗关闭 → 列表页顶部受理条（OA-09）→ 轮询 → 结果。抽屉内不套弹窗，按 `UI-D09` 先关抽屉。
- **弹窗内容（顺序固定）**：标题「停用 · 货主档案」；对象行「货主名称（OW000123）」；影响清单四条，逐条成句；停用原因文本域（3 行、`maxlength` 200、显示「0/200」）；底部「取消」与主按钮「停用」（危险色，`UI-W12` 主按钮用动作词，不用「确认」）。
- **影响清单文案（必须逐条显示，不得折叠）**：「停用后：所有仓库以该货主新建的业务将被拒绝；已存在的单据与任务继续执行至终态，不受影响；该货主名下账号立即拒绝登录，已登录会话在下一次请求被拒，数据保留在库；停用不会自动恢复，重新启用只能由具备写权限的人员发起并留痕。」
- **界面状态**：默认——原因为空、主按钮可点（点击时校验必填）；加载——提交中主按钮行内 spinner，右上关闭置灰保留、Esc 与遮罩点击禁用（`UI-D12`）；空——不适用；失败——弹窗关闭后在受理条内显示失败与出口，原因文本保留在受理条的重提面板（`UI-F03`）；无权限——`AUTHZ_2001` 按 `UI-S03`，`FORBIDDEN_OWNER` 按「不存在」处理。
- **文案口径**：动作词「停用」（`UI-W01`，不用「禁用」「关闭」）；失败提示按 `UI-W07` 三段——「货主档案停用失败 / …原因… / …下一步…（错误码）」。
- **恢复路径**：失败可「重试」（同一请求用原幂等键）；`STATE_INVALID`（已被他人停用）走「刷新查看」；`CONFLICT_VERSION` 走 OA-10；成功后列表行状态刷为「停用」，抽屉若重开会显示「启用」。
- **引用与新增**：复用 `UI-C05`、`UI-F05`、`UI-I04`、`UI-W12`、`UI-D09`、`UI-D12`；本次新增的是影响清单四条文案与「停用原因必填」的字段规格。按 `UI-C22` 的限定（气泡确认只用于轻量操作），货主停用影响他人且需必填原因，改用弹窗，见第 3 节待确认第 4 条。

### 1.7 OA-06 重新启用货主档案

- **触发**：详情抽屉底部「启用」（档案为停用态）。无写权限时按钮不渲染（`UI-X06`）。
- **动线**：与 OA-05 同构——抽屉「启用」→ 关抽屉 → 弹窗填启用原因 → 主按钮「启用」→ 202 → 受理条 → 轮询。
- **影响清单文案**：「启用后：所有仓库可再次以该货主新建业务；该货主名下账号可重新登录；货主编号与历史引用不变；停用期间被拒绝的业务不会补做。」
- **主按钮不用危险色**：启用不具破坏性，用主按钮语义（`UI-T01`）；停用才用危险色（`UI-T04`）。
- **界面状态、失败分派与恢复路径**：同 OA-05。额外一条：`STATE_INVALID`（当前已可用）的第三段写「刷新后查看当前状态」，出口为「刷新查看」，不提供「再次启用」。
- **引用与新增**：同 OA-05；本次新增的是启用影响清单与「无系统自动恢复」在界面上的一句明示（不提供任何「自动恢复」入口或定时动作）。

### 1.8 OA-07 开通货主端账号时选择货主

### 1.10 OA-09 受理票据的展示、轮询与落地

- **触发**：任一写操作（新建、编辑、停用、启用、开通货主端账号）返回 202 受理票据。
- **位置**：列表页与表单页的页头下方、筛选区上方，占一整行；受理条只由受理号驱动，无受理号时不渲染空条。
- **受理即状态（不得显示成功，`UI-F01`）**：状态标签「处理中」（`UI-C06` 圆点 + 文字）、受理号完整不截断且可复制（`UI-W16`）；`replayed=true` 时附一句「该请求此前已提交，沿用首次受理号」，避免被读成重复提交了两次。同一页面只保留最近一次受理条，形成新受理时替换旧条并给旧条一句「已由新的受理替换」。
- **轮询时机与间隔**：受理后 1 秒发起首次查询（覆盖秒级完成的情况），此后每 3 秒一次，最长 60 秒（`UI-F02`；契约同值）。60 秒仍未出结果时停止自动轮询，状态标签转「稍后查看」，受理号保留并给「重新查询」按钮，由人手动再查。
- **轮询自身失败**：429 按 `retryAfterMs` 拉长下一次间隔，不丢受理号、不转失败；503（`DEPENDENCY_UNAVAILABLE`）显示「受理结果查询暂时不可用」+「重新查询」，保留受理号；404（`NOT_FOUND_OWNER`：受理号不存在或不在数据域）显示「该受理号无法查询」+「返回列表」并停止轮询，连续 60 秒仍不可查时给「复制受理号联系运维」（`UI-I06` 求助出口）。
- **成功落地（`UI-F03`）**：状态整条替换为「已成功」，展示结果摘要（货主编号、状态、版本），同时按 `UI-F04` 给 2 秒轻提示「货主档案已建档，货主编号 OW000123」；列表与详情自动重取（`UI-X11`：只重取数据，不清筛选、不改游标）。
- **失败落地（`UI-F03`、`UI-S04`）**：状态整条替换为「已失败」，就地错误块给三段文案（`UI-W07`）与错误码（`UI-S06`），错误不用通知承载（`UI-C23`）；表单恢复可编辑并保留原输入，出口见 OA-10 的分派表。不出现「操作失败」这类空话，也不出现「系统繁忙」。
- **文案口径**：受理态用「处理中 / 已成功 / 已失败」，与业务状态词分开（`UI-W04`）；不显示百分比与假进度（`UI-C18` 无总量用 spinner）。
- **恢复路径**：每条失败都至少给「重试 / 修改输入 / 求助」之一（`UI-I06`）；受理号是持续的查询凭据，不因关闭提示或切页丢失在受理条内。
- **引用与新增**：复用 `UI-F01`~`UI-F04`、`UI-S04`、`UI-S06`、`UI-C23`、`UI-X11`；本次新增的是首次查询 1 秒、`replayed` 提示、同页只留最近一条受理条三条。

### 1.11 OA-10 版本冲突与受理失败的恢复

- **触发**：受理结果 `acceptStatus=FAILED` 且 `errorCode=CONFLICT_VERSION`；或同步返回的参数类、权限类、幂等类、限流类错误。
- **版本冲突的三段文案**：「货主档案改档失败 / 该货主档案已被他人修改，本次未写入 / 刷新后按最新数据重新提交（CONFLICT_VERSION）」。停用与启用场景把首段换成对应动作词。
- **版本冲突的两个出口（`UI-X12`，不静默重试、不自动覆盖）**：
  1. 「刷新查看」——重取详情拿最新值与最新版本号；表单以服务端最新值回填，**用户此前填写的内容不丢弃**，服务端值与当前输入不一致的字段在控件旁加一枚「已变更」标记（警告色 + 文字，双编码，`UI-T03`）；顶部提示「已载入最新数据（版本 N），请核对后重新提交」。
  2. 「放弃本次修改」——关闭表单页回列表，按 `UI-X10` 还原筛选、游标与滚动位置。
- **重提的幂等键**：刷新后重新提交必须换**新**幂等键——请求体已变，沿用原键会命中同键异体（`IDEMPOTENT_KEY_CONFLICT`）。规则一句话：**只有传输层的自动重试沿用原键，任何人工重新提交都换新键**。
- **其余受理失败的出口分派**：

| 错误码 | 出现位置 | 第三段（下一步） | 出口 | 幂等键 |
|---|---|---|---|---|
| `RULE_DUPLICATE_CREDIT_CODE` | 受理结果 | 核对信用代码是否属于其他主体 | 「修改输入」「按信用代码筛选列表」 | 新键 |
| `STATE_INVALID` | 受理结果 | 刷新后按当前状态操作；停用态改档需先启用 | 「刷新查看」「返回列表」 | 新键 |
| `CONFLICT_VERSION` | 受理结果 | 刷新后按最新数据重新提交 | 「刷新查看」「放弃本次修改」 | 新键 |
| `NOT_FOUND_OWNER` | 受理结果 | 货主不存在或已不在你的数据域内 | 「返回列表」 | — |
| `DEPENDENCY_UNAVAILABLE` | 同步或受理结果 | 稍后重试，不改为查空结果 | 「重试」（按 `retryAfterMs` 退避） | 原键 |
| `INTERNAL_ERROR` | 同步或受理结果 | 带 traceId 报障 | 「重新提交」「复制 traceId」 | 新键 |
| `RATE_LIMITED` | 同步 | 按提示时间后再试 | 按钮显示倒计时并禁用 | 原键 |
| `IDEMPOTENT_IN_PROGRESS` | 同步 | 同一请求正在处理中，勿换键 | 按钮按 `retryAfterMs` 倒计时后自动用原键重提 | 原键 |
| `IDEMPOTENT_KEY_CONFLICT` | 同步 | 本次内容与首次提交不一致 | 「重新提交」（换新键） | 新键 |
| `PARAM_INVALID` | 同步 | 按 `details[].field` 修正 | 就地标注该字段并聚焦 | 新键 |
| `FORBIDDEN_OWNER` | 同步 | 无该货主的数据域权限 | 按 `UI-S03` + 「返回上一页」 | — |

- **不做什么**：不做前端业务判定（`UI-I11`）——信用代码是否重复、能否停用、版本是否最新一律以服务端返回为准；不在冲突时静默合并、不自动重发。
- **引用与新增**：复用 `UI-X12`、`UI-F03`、`UI-I06`、`UI-W07`、`UI-S04`、`UI-S06`；本次新增的是「已变更」字段标记、刷新不丢输入与新键重提规则。

### 2.2 复用统一抽屉骨架的方式

详情抽屉一律复用共享外壳 `DetailDrawer`，页面只传数据与分区，不在页面内自写 `el-drawer`、自拼头部、目录、分隔线与字段皮肤（`UI-D04`）；外壳不满足需求时改组件，不改页面（`UI-D13`）。传参固定如下：

| 传参 | 本次取值 | 依据 |
|---|---|---|
| `title` | 货主名称 | `UI-D04` |
| `subtitle` | 「货主编号 OW000123」 | `UI-D06` |

# Proposal

## Why

`check-design.py` 的检查项按「有接口、有表结构」的功能变更设计：`API-01` 要求契约章至少有一条接口条目，`BE-03`~`BE-07` 要求库存表关键字段与 CHECK，`FE-03`~`FE-05` 要求受理号、数据时间戳与权限点并入。

纯呈现层变更与工具类变更没有这些内容，即使如实写明「本次不涉及」，`API-01` 仍然报 ERROR，因为它是结构性的：没有接口条目就不过。结果是任何纯前端改造都被迫破门禁或登记例外，门禁失去约束力。

本次变更 `refine-admin-shell-ui` 已实测复现：8 个 ERROR 中 7 个可用「不适用说明」如实消除，只剩 `API-01` 无法通过。

## What Changes

- 新增「窄范围变更」识别：`design.md` 同时满足三条时认定为窄范围——契约章无任何接口条目、契约章含声明「本次无接口变更」、后端章含声明「本次无表结构变更」。
- 窄范围变更跳过下列结构性检查，并逐项以 INFO 登记「已豁免」：`API-01`、`BE-03`、`BE-04`、`BE-05`、`BE-06`、`BE-07`、`FE-03`、`FE-04`、`FE-05`。
- 保留对纯呈现层同样适用的检查：三章结构、`INV` 与 `D` 编号闭合、禁用词、错误码表、鲁棒性与幂等三节、五类页面状态、页面与接口映射、tasks 联调引用闭合。
- 补充 `--list-checks` 输出与 `.codebuddy/references/校验指南.md` 的说明，写清豁免条件与不可豁免项。

**不做**：

- 不删除任何检查项，不放松已有判定；只要存在接口条目或表结构变更，行为与当前完全一致。
- 不引入命令行开关（如 `--frontend-only`）：开关一旦带上就全放行，无法保证与文档内容一致；改用文档内的显式声明识别。
- 不改检查编号、分组与退出码含义。

## Capabilities

### New Capabilities

- `change-scope-check`: 变更范围识别与检查项适用性判定，规定哪些检查对窄范围变更豁免、豁免如何留痕、以及不可豁免的范围。

### Modified Capabilities

无。

## Impact

- 工具：`.codebuddy/tools/check-design.py` 增加窄范围识别与九个检查项的跳过分支，其余逻辑不动。
- 参考资料：`.codebuddy/references/校验指南.md` 补一节说明。
- 变更产物：`refine-admin-shell-ui` 可去掉为凑检查而写的关键词段，只保留真实的适用性说明。
- 后端、前端、契约、数据库：无改动。

# Spec Delta

## Purpose

让设计文档校验器区分「有接口与表结构的功能变更」和「窄范围变更」，避免纯呈现层或工具类变更因无可写的接口条目而被结构性判红，同时保证豁免只对真正没写接口、没写表结构的变更生效。

## ADDED Requirements

### Requirement: 窄范围变更识别

校验器 SHALL 在 `design.md` 同时满足下列三条时把本次变更认定为窄范围：

1. 契约章存在且没有任何 `### API-xxx` 接口条目；
2. 契约章含显式声明「本次无接口变更」；
3. 后端设计章含显式声明「本次无表结构变更」。

三条缺一不可。识别 MUST 基于文档内容，不读取命令行参数或外部配置。

#### Scenario: 纯呈现层变更被识别
- **WHEN** 变更的契约章写明「本次无接口变更」且无接口条目，后端章写明「本次无表结构变更」
- **THEN** 校验器按窄范围变更执行，跳过结构性检查并逐项输出 INFO

#### Scenario: 只写声明不满足条件
- **WHEN** 契约章写了「本次无接口变更」，但仍定义了至少一条接口条目
- **THEN** 不认定为窄范围，接口条目按原有规则逐项校验

#### Scenario: 缺声明不豁免
- **WHEN** 契约章没有任何接口条目，但未写「本次无接口变更」或后端章未写「本次无表结构变更」
- **THEN** 维持现状，`API-01` 与库存表相关检查照常报错

### Requirement: 豁免与保留范围

窄范围变更 SHALL 跳过下列检查并以 INFO 逐项登记：`API-01`、`BE-03`、`BE-04`、`BE-05`、`BE-06`、`BE-07`、`FE-03`、`FE-04`、`FE-05`。

下列检查 MUST NOT 豁免，窄范围变更同样要过：三章结构与顺序、`INV` 与 `D` 编号在 `00` 中真实存在、红线禁用词、错误码表列齐全、鲁棒性与幂等三节、五类页面状态、页面与接口映射闭合、tasks 联调引用闭合、版本门禁。

#### Scenario: 窄范围变更缺错误码表列
- **WHEN** 窄范围变更的错误码表缺少「调用方处置」列
- **THEN** 仍按 `API-14` 报 WARN，不因豁免而沉默

#### Scenario: 窄范围变更出现禁用词
- **WHEN** 窄范围变更的后端章出现「VIRTUAL」等红线禁用词
- **THEN** 仍按禁用词检查报 ERROR

### Requirement: 豁免留痕

每次豁免 MUST 在校验输出中可见：以 INFO 级别写明被豁免的检查编号与判定依据，且不得把豁免计入 WARN 或 ERROR 统计。

#### Scenario: 豁免可在输出中核对
- **WHEN** 窄范围变更通过校验
- **THEN** 输出包含 INFO 级条目，列明 `API-01`、`BE-03`~`BE-07`、`FE-03`~`FE-05` 因窄范围被跳过

### Requirement: 有接口的变更行为不变

对存在接口条目或表结构变更的变更，校验器 MUST 与改造前逐项一致：检查项、级别、退出码均不改变。

#### Scenario: 功能变更回归
- **WHEN** 用改造后的校验器校验 `add-three-end-product-archive` 与既有正式规格
- **THEN** 输出与改造前一致，不新增 INFO 豁免，不减少 ERROR

### Requirement: 豁免不可掩盖真实缺失

窄范围认定 MUST 只看结构性与库存表类要求；文档内容缺失（如窄范围变更未写页面状态、未写契约验收）MUST 继续按原规则报出，不得因窄范围而免写。

#### Scenario: 窄范围变更未写契约验收
- **WHEN** 窄范围变更的契约章缺少「契约验收」一节
- **THEN** 按 `API-11` 报 ERROR，不因窄范围豁免

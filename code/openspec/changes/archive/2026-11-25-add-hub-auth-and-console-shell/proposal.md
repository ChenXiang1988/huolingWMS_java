# Proposal

## Why

运营端是主数据与仓网调度的权威源，也是全系统第一个要能登录、能被人看到的端。当前后端只有四个可启动的空壳，没有登录、没有会话、没有任何一条接口做过权限声明；前端连工程目录都还没有。这意味着后续每一个业务页面落地时，都要临时决定「谁能看、谁能改」，权限口径会散进各页代码，再收回来成本极高。

现在做的理由有三个：一是 `19` 已把四道门、七张表、权限点代码声明、数据域合并规则定清楚，实现有唯一依据；二是决三（权限缓存失效机制）一直待拍板，而鉴权链路不落就无法开工，本次必须一并定下；三是 `12a` 的 `UI-P04` 与五类页面骨架已定，展示框架有现成规格可以照做，不需要重新设计界面。

## What Changes

- **运营端登录与会话**：账号密码登录、密码存储、令牌签发与刷新、登出、会话超时。令牌只放身份，权限不进令牌。
- **四道门鉴权**：令牌有效性、接口权限点、会话固定域与配置域合并、仓储层数据域注入。四道门缺一不可，任一失败按 `19` 的返回码拒绝。
- **权限点代码声明与启动同步**：接口以注解声明权限点，启动时扫描并与 `permission` 表双向对账；白名单外未声明权限点的接口直接启动失败。
- **权限配置全量页面**：账号管理、角色管理、权限点分配、数据域配置四组页面，由权限管理员维护。
- **运营后台展示框架**：`UI-P04` 的顶栏 56、侧边菜单展开 200／收起 64、内容区 1200~1440 居中；路由骨架；菜单与按钮按权限点生成；令牌变量唯一入口；通用组件封装（表格、筛选区、表单、右侧抽屉）。
- **决三拍板**：权限缓存失效采用全局版本号——任何授权动作使全局版本号加一，旧键自然不再命中。同步更新 `05`、`19`、`23` 的相关表述。
- **BREAKING**：新增接口必须声明权限点，否则应用启动失败。这条对后续所有接口生效，是本次交付后新增的硬约束。

## Capabilities

### New Capabilities

- `hub-access-control`：运营端的登录、令牌、会话、四道门鉴权、数据域合并与注入、异常返回。
- `hub-permission-admin`：账号、角色、权限点分配、数据域配置的维护规则，含授权不能自授、至少保留一个权限管理员、角色不跨端合并。
- `console-shell`：运营后台的页面外壳与骨架——布局尺寸、路由、菜单生成、令牌入口、通用组件外壳与各端密度参数。

### Modified Capabilities

无。当前 `openspec/specs/` 为空，本变更是第一批能力规格，不涉及既有能力的增量修改。

## Impact

**后端**：`code/backend/wms-hub` 首次落地四层代码与数据库访问；新增依赖 Spring Security、JWT、MyBatis-Plus、Flyway、PostgreSQL 驱动、Redis 客户端。新增七张表 `account`、`role`、`permission`、`role_permission`、`account_role`、`role_scope`、`role_scope_item`，迁移脚本落 `code/db/migration/hub/`。`wms-kernel` 新增身份与权限的领域模型，但不得依赖框架（AR-02）。

**前端**：新建 `code/web`，包含 `apps/admin`（运营后台）与共享包 `packages/design`、`packages/request`、`packages/dict`。本变更只建运营后台一个应用，单仓端与货主端等决六拍板。

**契约**：`wms-hub` 用 SpringDoc 导出 `openapi.json` 到 `code/contracts/`，前端类型由生成物产出，不手写请求体。

**设计文档**：决三拍板后需同步 `05`、`19`、`23` 三处，并把本变更落定的权限点编码前缀写进 `19`。`01` 需补第七个 Maven 模块 `wms-archtest` 与计费域端口 8084。

**全局约束**：权限点缺失即启动失败这条生效后，任何新增接口不声明权限点都无法启动，包括后续单仓端与接入层的接口。

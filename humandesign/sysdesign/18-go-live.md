# 上线与数据迁移

期初库存只从实盘来，不从旧系统导账面数；迁移的是主数据，库存只建账。

---

## 问题

**解决**：定住第一个仓怎么建账、哪些数据可以迁、上线窗口怎么切、失败怎么回退。

**不解决**：日常盘点流程（见 04 与 13 的两段式盘点结论）、计费起始日与费率生效（见 08）、账号与角色初始化细则（见 05）、历史单据归档（见 11）。

---

## 设计

### 期初库存只认实盘，不认旧账

旧系统的账面数与实物偏差幅度未知，导入等于把别处的错原样搬进来，之后每次盘点都在还这笔债。

流程固定五步，不可跳过、不可并行：

| 步 | 动作 | 完成判定 |
|---|---|---|
| 一 | 停业，冻结全仓库位 | 无进行中任务，无未结单据 |
| 二 | 全仓实盘 | 每个库位都有实盘记录，无遗漏 |
| 三 | 差异确认 | 货主逐条确认差异原因 |
| 四 | 建账 | 盘点单入账，产生库存流水 |
| 五 | 解冻 | 三个数对齐后开放作业 |

### 迁移主数据，不迁移库存与历史单据

| 数据 | 处理 | 核对方式 |
|---|---|---|
| 货主档案 | 导入 | 人工逐条核对 |
| SKU 档案 | 导入 | 抽样扫条码核对 |
| 库位 | 现场贴码后导入 | 逐个扫码确认坐标 |
| 员工与账号 | 单仓端建档并开通账号；单仓管理者角色按需授予 | 按角色抽检登录 |
| 合同 | 上线前必须生效 | 校验生效状态（D33） |
| 存量库存 | 不导入，实盘建账 | 见上节 |
| 历史单据 | 不迁移，旧系统只读保留 | — |

库位不能只导入坐标就完事：码贴在墙上、坐标对不上，是上线后最常见的错。每个库位启用前必须现场扫一遍。

### 建账走盘点单，不直接写库存

期初库存以盘点差异入账，产生正常的库存事务流水，保证 INV-09 从第一天就成立。禁止用 SQL 直接插库存表——那会让期初成为唯一没有流水来源的库存，之后对账永远差一笔。

### 解冻的判定是三个数对齐

实盘数、系统库存、盘点单结果三者一致才允许解冻。任何一个对不上，退回差异确认，不部分解冻。

### 停业窗口按工作量排，不按天排

一个仓的实盘通常占用一个班次，窗口长度由库位数与 SKU 数决定。旧系统只读保留，不做双写；并行期只做只读对照，时长由业务方定，不作为技术依赖。

解冻后第一笔作业之前必须完成第一次日结，作为后续对账的基线。

### 第二个仓起没有存量，但库位贴码不能省

新仓上线只有库位建码与主数据，没有期初库存。库位码照旧现场贴、现场扫，这一步省掉，后面所有上架都可能上错位置。

### 建账失败退回冻结态

差异无法确认时整体退回冻结，不保留部分已入账结果。已完成的实盘记录保留，次日继续，不重新盘。

## 约束与验证

| 约束 | 强制手段 |
|---|---|
| 期初库存不得来自导入 | 上线检查：库存表首条流水的来源必须是盘点单 |
| 建账不得绕过流水 | 账号权限：人工操作账号无库存表写权限，入账只走应用 |
| 合同先于作业生效 | 应用校验 D33；上线检查清单逐项打勾 |
| 库位坐标必须现场指认 | 启用前扫码一次并留痕，未扫码的库位不得启用 |
| 解冻前三个数必须一致 | 盘点单状态机：三者不一致时无法流转到已入账 |
| 停业期间不得有作业 | 冻结态下作业接口全部拒绝，移动作业端显示仓库未开放 |

引用的决策编号：D33、D62；不变量：INV-01、INV-09、INV-12。盘点两段式的做法见 13；库存模型与库位定义见 04；历史数据归档见 11。

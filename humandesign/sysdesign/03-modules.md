# 模块划分与依赖

内核按业务能力切成十一个模块，每个模块独占自己的表；依赖只允许从单据流向任务、从任务流向库存，反向一律通过事件；每个模块内部固定四层，领域层不认识框架。

---

## 问题

**解决**：定住内核的模块清单、模块之间允许的依赖方向、模块内部分层、跨模块协作的两种方式与禁止事项。

**不解决**：模块内部的具体模型与状态机（单据见 00 D56，库位与库存见 04，任务见 06）、表结构（见 11）、仓型差异的具体规则（见 07）、计费算法（见 08）。

---

## 设计

### 内核按业务能力切十一个模块，每个模块独占自己的表

| 编号 | 模块 | 负责的对象 | 明确不负责 |
|---|---|---|---|
| M01 | 货主与主数据 | 货主、SKU、批次属性、角色权限、员工副本 | 不存库位、不存库存、不建仓内员工档案（归 M11） |
| M02 | 库位 | 库区（含温区）、巷道、货架、层、格、坐标、容量属性 | 不存库存数量 |
| M03 | 库存 | 库存台账、库存流水、锁定与释放 | 不知道变动由哪张单据发起 |
| M04 | 任务 | 任务树、任务状态、指派、作业量核算 | 不决定库存怎么变 |
| M05 | 单据 | 入库单、出库单、移库单、盘点单 | 不直接写库存 |
| M06 | 策略 | 上架选址、分配、波次、仓型能力矩阵的接口 | 不含任何仓型的硬编码分支 |
| M07 | 加工 | 加工单、物料清单、在制、损耗 | 不维护库存台账 |
| M08 | 作业事实 | 作业事实、停租事实、耗材事实的产生与投递 | 不算费、不对账、不生成账单（计费在独立域，见 00 D49） |
| M09 | 设备 | 设备台账、能力、状态、绑定关系 | 不做采购、维修、固资 |
| M10 | 仓库与仓网 | 仓库档案、仓型（楼层仓 / 平面仓）、层高与面积、监管区域标记、作业日历 | 不存库位坐标、不存库存数量、不维护货主授权、不建楼层对象、不做保税账册 |
| M11 | 班组与人员 | 本仓员工档案、班组树、班组归属与职务、临时支援、代班、可作业资格、登录状态可见性 | 不写角色权限（调权限接口）、不做考勤与排班（见 00 D61） |

M10 是单仓执行端的根模块：`warehouse_id` 出现在库位、库存、任务、单据的每一行上。字段按段分权威：档案、仓型、五态状态归 Hub；作业日历归 Site（见 00 D12）。

仓库五态为拟定、已部署、生效、停用、归档，只有「生效」才接单（见 00 D41）。单仓端不自建仓库，绑定校验不过就拒绝启动。

本模块不维护「货主—仓库」关系：货主开通即全仓网可见；作业准入校验的是货主的合同，不按仓判断（见 00 D40、D32、D33）。

表的归属规则：一张表只能由一个模块写入。其他模块需要读，走查询服务（见下），不得直接持有该表的写权限。

依据 D02、D10、D12、D22。

### 单据不直接写库存，依赖只能单向往下

```
M05 单据 ──→ M04 任务 ──→ M03 库存
   │            │            ↑
   └────────────┴──→ M06 策略（选址与分配）
M04 ──→ M11 班组与人员（只读派工候选）
M11 ──→ M01 主数据（上行员工副本、申请账号与角色）
M07 加工 ──→ M05 / M04
M08 计费事实 ←── 被 M03 / M04 / M07 写入
M09 设备 ←── 被 M04 调用（下发与回调）
M01、M02、M10、M11 ←── 被需要的模块读取
```

M11 与 M01 分属 Site 与 Hub，图中箭头表示消息与接口调用，不是代码依赖；两边不共享代码包。

| 规则 | 内容 |
|---|---|
| 允许向下 | M05 依赖 M04；M04 依赖 M03；M05、M04 依赖 M06 |
| 禁止反向 | M03 不得依赖 M04、M05；M04 不得依赖 M05 |
| 禁止跨层 | M05 不得直接调用 M03 的写入接口 |
| 禁止反向写 | M08 只被写入，不反向依赖任何模块 |
| 禁止业务依赖设备 | M09 不认识单据与任务，只提供能力与状态 |
| 根对象只读 | M10 只被其他模块读取与校验，不依赖 M03 至 M09 |
| 只读班组 | M04 读 M11 的已登录与班组候选，M11 不依赖 M04 |
| 独占 Site 员工表 | M11 写本仓全部员工档案；员工档案只有一份；角色与账号经 M01 权限接口 |

反向信息的处理：任务完成要改单据状态，由 M04 发领域事件，M05 订阅后自行更新。不允许 M04 调 M05 的接口。

依据 D09、INV-09。

这条规则的目的是守住"库存变动必有任务"：如果允许单据直接写库存，任务层就被绕过，INV-10 的分片校验与 INV-11 的已分配未执行都失去落点。

**例外机制**：若某个业务场景确实不需要任务层（例如越库直发、整托直入），该场景必须在 00 登记为显式例外，并说明它如何满足 INV-09 与 INV-11；未经登记的场景一律按上表执行。本文件不预判哪些场景属于例外。

### 每个模块内部固定四层，领域层不认识框架

| 层 | 放什么 | 允许依赖 |
|---|---|---|
| domain | 实体、值对象、不变量、领域服务接口、仓储接口 | 只依赖本模块 domain 与 M01 的值对象 |
| application | 用例编排、事务边界、跨模块调用 | 本模块 domain、本模块 infrastructure（仅通过接口）、其他模块的 application 接口 |
| infrastructure | 持久化实现、外部调用实现 | 本模块 domain 的接口 |
| api | 对外契约：请求响应对象、错误码映射 | 本模块 application |

三条硬规则：

1. domain 层不得出现框架注解，也不得依赖 Spring。这是 01 里"内核不依赖 Spring"的落点。
2. repository 接口在 domain，实现在 infrastructure，只能被本模块 application 注入。
3. 跨模块只能调对方的 application 接口，不能调对方的 repository，也不能注入对方的 infrastructure。

### 跨模块只允许两种协作：应用服务调用与领域事件

| 方式 | 适用 | 事务边界 | 例子 |
|---|---|---|---|
| 应用服务调用 | 需要立即拿到结果，且必须同事务 | 调用方事务内 | 单据生成任务、任务锁定库存 |
| 领域事件 | 不要求立即完成，或方向必须反过来 | 提交后投递 | 任务完成通知单据、作业事实进计费 |

领域事件必须先落本地消息表，事务提交后投递，失败靠定时补偿。队列用 01 定下的 RabbitMQ，不用进程内事件总线（多副本会丢事件，依据见 13）。

禁止两种做法：跨模块共享一张中间表；跨模块直接传递实体对象，只能传本模块 api 层定义的 DTO。

### 跨模块联表查询只能走只读查询服务

报表、看板、列表页需要跨模块字段时：

| 做法 | 是否允许 | 条件 |
|---|---|---|
| 各模块自己查自己的表，应用层拼装 | 允许 | 默认方式 |
| 只读查询服务里写联表 SQL | 允许 | 只读、不写、不承载业务判断、字段变更需同步改查询 |
| 建物化视图或汇总表 | 允许 | 必须有刷新机制与延迟上限说明 |
| 业务模块互相注入 repository | 禁止 | — |

依据 D11：报表与看板是最终一致，允许延迟；但库存可用量的实时查询不能走这条路（见 04、11）。

### 策略实现放在单仓端，内核只留接口

| 位置 | 内容 |
|---|---|
| 内核 M06 | 只定义接口：上架选址、库存分配、任务拆分、仓型能力查询 |
| 单仓端 | 提供实现，按仓型配置选择具体实现类；维护本仓作业策略参数（见 00 D59） |
| 运营端 | 只维护仓型能力矩阵与仓库档案；不维护作业策略参数，不下发实现代码 |

判断标准沿用 D10：新增一个仓型时如果需要改内核代码，说明切错了。

策略实现的默认装载方式是"仓级配置指定实现 + 缺省实现兜底"，不允许在业务代码里写 `if (warehouseType == 冷链)` 这类分支。

## 约束与验证

| 约束 | 强制手段 |
|---|---|
| 一张表只有一个模块写 | 构建层：按模块划分数据源账号与写权限；代码层：ArchUnit 规则禁止跨模块 mapper 引用 |
| 依赖只能单向 | 构建层：Maven 模块依赖图检查；代码层：ArchUnit 分层规则 |
| 单据不得直接写库存 | 代码层：库存写入接口只在 M03 的 application 暴露，M05 的依赖白名单不含它 |
| 反向信息只走事件 | 代码层：ArchUnit 禁止 M03、M04 引用 M05 的包 |
| domain 不含框架 | 代码层：ArchUnit 禁止 domain 包引用 Spring 与 MyBatis |
| 聚合根不暴露 setter | 编译期：聚合根只用 `@Getter`，不生成 setter，Service 想改也改不了；构建期：ArchUnit 断言 domain 包内不存在 `set` 开头的 public 方法 |
| 聚合根必须有行为 | 构建期：聚合根标 `@AggregateRoot`，ArchUnit 断言除去 getter、equals、hashCode、toString 后至少有一个 public 方法 |
| 状态只能由聚合根自己改 | 编译期：状态字段 private 且无 setter；构建期：ArchUnit 断言状态变更方法只在 domain 包内声明 |
| 值对象不可变 | 编译期：字段 `final`、无 setter、构造器内校验；构建期：ArchUnit 断言值对象无 public setter |
| 领域事件只能由 domain 发 | 编译期：发布入口在 domain 包内、包级可见；构建期：ArchUnit 断言调用方必须位于 domain 包 |
| 跨模块只传 DTO | 代码层：ArchUnit 禁止其他模块引用本模块 domain 实体类 |
| 策略不得硬编码仓型 | 构建期：CI 关键字扫描，业务包内出现仓型枚举比较即失败；不靠人工评审 |
| 班组表只由 M11 写 | 构建层：按模块划分数据源账号；ArchUnit 禁止其他模块引用 M11 的 mapper |
| Site 员工表只由 M11 写 | 构建层：Site 数据源账号只授 M11；员工档案只有一份 |
| 角色权限只由 M01 写 | 构建层：单仓端只调权限接口，不写角色权限表 |
| 模块清单变更 | 必须改本文件并记入 `log.md`；新增模块需说明它独占哪张表 |

引用的决策编号：D02、D09、D10、D11、D12、D22、D60、D61、D62；不变量：INV-09、INV-10、INV-11。

上表每条手段的断言写法见 [14 构建约束与自动检查](14-构建约束与自动检查.md)，十条规则全部在构建期失败阻断，不设人工评审环节。

模块内部的对象与状态见 00 D56（单据框架）、04（库位与库存）、06（任务拆分）、20（班组与人员）；表结构与并发实现见 11。

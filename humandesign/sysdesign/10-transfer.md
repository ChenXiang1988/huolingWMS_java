# 跨仓调拨

调拨是一张调拨单加两张本地单据：源仓发运即减库存、目的仓收货才增库存，全程没有在途库存；调拨单只做下发与进度归集，不碰任何库存表。

---

## 问题

**解决**：定住调拨的对象结构、两段执行、库存时点、状态怎么归集、跨法域怎么传、异常怎么收口、与计费的关系。

**不解决**：物流段运输（承运商、车辆、运费，属 TMS）、发运后的在途跟踪、库存模型（见 04）、单据结构（见 16）、货权转移（首期不做）。

---

## 设计

### 一张调拨单加两张本地单据，各有归属

依据 D14 与 D56 的单据边界（一单一货主一仓）。

| 对象 | 归属 | 作用 | 能否改库存 |
|---|---|---|---|
| 调拨单 | 仓网运营（Hub） | 计划：从哪仓到哪仓、调什么、多少 | **不能** |
| 源仓出库单 | 源仓 Site | 本地执行：拣货、复核、发运 | 能（经任务） |
| 目的仓入库单 | 目的仓 Site | 本地执行：收货、上架 | 能（经任务） |

调拨单是**计划对象**，两张本地单据是**执行对象**。调拨单不产生任务，任务由两张本地单据各自生成。

### 三份单据靠父单号串起来

| 字段 | 位置 | 内容 |
|---|---|---|
| 父单号 | 源仓出库单单头的「关联」组 | 调拨单号 |
| 父单号 | 目的仓入库单单头的「关联」组 | 调拨单号 |
| 子单号 | 调拨单的关联记录 | 两张本地单据的单号 |

不新建一张「调拨关系表」：父单号写在单头六组的关联组里（见 D56），查询时按父单号反查即可。

### 调拨单的状态是归集值，不是自己推进的

调拨单也有五态，但它的状态由两张本地单据归集得出：

| 调拨单状态 | 归集条件 |
|---|---|
| 已受理 | 已下发到两仓，两张本地单据都生成 |
| 执行中 | 任一本地单据处于执行中 |
| 已完成 | 两张本地单据都已完成 |
| 差异关闭 | 任一方差异关闭（短发或短收）且人工确认 |
| 已取消 | 两张本地单据都已取消 |

这与单据五态"只由任务事件推进"同源，只是汇总层级更高一层。**调拨单不能自己跳到已完成**——必须两张子单都完成。

### 库存时点：源仓发运即减，目的仓收货才增

```
源仓：拣货 → 复核 → 发运   ← 此刻库存已减，账上不再属于任何仓
      ──── 物流段，WMS 不记账 ────
目的仓：收货 → 上架        ← 此刻库存才增
```

三条直接后果：

1. **在途期间，全仓网库存总量是少的**。这是正确行为：货不在任何仓库里，账上就不该有。
2. **没有「在途仓」这个对象**（D14 否决）。任何"在途库存"的查询，本质是查调拨单的未收货数量，不是查库存表。
3. **两端不保证一致，也不需要一致**。源仓发 100、目的仓收 98，中间差的 2 件是货损或丢失，走差异，不需要"平账"。

### 在途期间能查到什么、查不到什么

| 想查 | 从哪查 | 结果 |
|---|---|---|
| 这批货到哪了 | 调拨单状态 + 源仓发运时间 | 能查到"已发运、未收货" |
| 这批货现在有多少库存 | 库存表 | **查不到**，在途不是库存 |
| 在途总量 | 调拨单未收货数量汇总 | 能查到，但这是单据量不是库存量 |

仪表盘上如果出现「在途库存」这个指标，必须注明它是调拨单数量汇总，不能与库存相加。

### 跨法域调拨只传摘要

依据 D07。

| 内容 | 是否过境 | 说明 |
|---|---|---|
| 调拨单头：数量、状态、时间 | 是 | 跨仓调度与客户查询需要 |
| SKU 编码 | 是 | 需货主确认编码在两地一致 |
| 批次、库位、序列号明细 | **否** | 明细不出境 |
| 收货方与客户信息 | 否 | 属地管理 |

**这里有一个必须业务确认的约束**：批次明细不过境，目的仓收货时拿不到源仓的批次号，只能靠随货纸单或现场扫码重新录入。

由此产生两种可行做法，需要业务选一种：

| 做法 | 代价 |
|---|---|
| 批次清单随货走纸质单据，目的仓手工录入 | 录入错误风险，需双人复核 |
| 批次号编码规则全球统一，目的仓按规则重算 | 要求两地 SKU 与批次编码同源 |

首期若跨法域调拨量小，建议第一种，在收货环节强制扫码校验。

### 下发与回传

| 方向 | 内容 | 方式 |
|---|---|---|
| Hub → 源仓、目的仓 | 调拨单与对应的本地单据草稿 | 消息下行，拉取兜底 |
| 源仓、目的仓 → Hub | 本地单据状态、实发量与实收量 | 事件上行 |
| 跨法域 | 只传摘要 | 见上 |

回传只传状态与数量，不传明细。Hub 侧按父单号归集调拨单状态。

### 调拨不产生跨仓事务

两段各自是本地事务，中间没有分布式事务，也没有 Saga 补偿。

| 情形 | 处理 |
|---|---|
| 源仓发运成功，目的仓一直没收到 | 调拨单停在执行中；超期告警，人工核查物流 |
| 目的仓拒收 | 目的仓入库单取消；货退回源仓需**新建一张反向调拨单**，不能复用原单 |
| 源仓发运失败 | 源仓出库单取消；调拨单回已受理，可重新生成子单 |

不引入补偿事务的理由：库存本来就是两段，中间没有"待定"状态，补偿反而会造出一个不存在的中间态。

### 异常只有四种，各有唯一出口

| 异常 | 处理 | 落点 |
|---|---|---|
| 源仓短发（计划 100、实发 90） | 源仓出库单差异关闭；调拨单差异关闭；目的仓按 90 收 | 差异关闭态 |
| 目的仓短收（源发 90、实收 88） | 目的仓入库单差异关闭；差 2 件走异常记录 + 调整单 | 差异关闭态 |
| 货损 | 在发生地报废，走报废库位与损耗流程 | 加工单或报废流程 |
| 目的仓拒收 | 目的仓入库单取消；新建反向调拨单退回 | 取消 + 新单 |

**不允许「发 90 收 100」**。多出的部分必须有来源单据（另一张调拨单、本地采购入库或盘盈），不能凭空出现在收货环节。

### 调拨单不写库存，这是硬边界

依据 15 的领域划分：跨仓调度只做下发与归集，不做库存扣减。

| 对象 | 能做 | 不能做 |
|---|---|---|
| 调拨单 | 记录计划、归集状态、统计在途量 | 直接改任何一仓的库存 |
| 源仓出库单 | 生成拣货与发运任务 | 直接改目的仓的任何数据 |
| 目的仓入库单 | 生成收货与上架任务 | 直接改源仓的任何数据 |

库存变动只能由各仓本地任务触发（见 06），调拨单只是提供了「为什么要搬」的理由。

### 计费事实各仓各记，调拨本身不加价

| 仓 | 产生什么事实 | 依据 |
|---|---|---|
| 源仓 | 出库操作费、拣货费、复核费、装车费 | 08 的事实类型 |
| 目的仓 | 收货操作费、上架费 | 同上 |
| 调拨本身 | 不产生额外费用 | 除非费率卡里单独配了「调拨服务费」 |

同一货主的货从 A 仓到 B 仓，货主没变，所以合同不变，费率按各仓的维度匹配。

### 调拨不改变货权

调拨只搬货，不换货主。货主之间的转移是「货权转移」，涉及结算与合同变更，首期不做。

## 约束与验证

| 约束 | 强制手段 |
|---|---|
| 无在途库存 | 数据库层：不存在在途库存表；核对层：日结校验全仓网库存总量 + 调拨在途单据量 = 期初 + 入 − 出，口径必须写明 |
| 调拨单不写库存 | 代码层：调拨模块不引用库存写入接口，ArchUnit 断言 AR-09（见 14） |
| 一单一货主一仓 | 数据库层：三张单据的 `owner_id` 必须相同、`warehouse_id` 各不相同；应用层：下发时校验 |
| 状态只能归集 | 应用层：调拨单状态由子单状态计算写入，不开放人工修改；核对层：日结比对调拨单状态与子单状态 |
| 跨法域只传摘要 | 集成层：跨境报文白名单字段，出现批次或明细字段即拒绝 |
| 短发短收必须留痕 | 数据库层：差异关闭时差异量、原因、确认人非空 |
| 不得超发超收 | 应用层：实收量大于源仓实发量时拒绝收货，除非关联另一张来源单据 |
| 反向退货必须新单 | 应用层：不允许在原调拨单上做「反向执行」，只能新建 |

引用的决策编号：D07、D14、D19、D56；单据结构见 16，任务生成见 06，库存变动见 04，事实与计费见 08。

物流段的承运商选择、运费结算、在途轨迹不在本文范围：那是 TMS 的职责，WMS 只关心「发了多少」与「收了多少」。

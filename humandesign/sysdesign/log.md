## 决策变更溯源

### 2026-11-24 首次设计讨论

本次讨论共推翻六项初版设计，记录原因以便后续追溯：

| 原设计 | 修正为 | 触发原因 |
|---|---|---|
| SaaS 多租户，`tenant` 为最外层隔离 | 无租户，货主为唯一隔离维度 | 运营方自用单套部署，不是 SaaS |
| 内部货主 + 内部结算价 | 所有货主同构，差异只在合同 | 不要内部货主，不留特权分支 |
| 单实例多仓、一个主库 | Hub / Site 两级部署，Hub 按法域分区 | 单仓可能跨国，不可能共用一个集群 |
| PDA 离线执行端（本地库 + 同步引擎 + 规则双份） | PDA 在线终端（重试 + 幂等） | 不考虑断网 |
| 登录时扫设备码确认设备身份 | 设备激活时一次性绑定凭证 | App 本身已知设备身份，扫码冗余 |
| 库位状态含「占用 / 空闲」 | 库位无占用状态，占用实时计算 | 混存后占用是渐变量，状态字段会互相覆盖 |
| 合同挂「货主 + 仓库」，每个仓一份 | 合同挂「货主」，一份覆盖全仓网；仓型、仓、库区的费率差异放进费率卡维度 | 合同是货主与仓网运营方签的，不是与单个仓签 |
| 仓型分常温 / 冷链 / 危化 / 保税四类 | 仓型只分楼层仓与平面仓；温区与监管不混进仓型枚举 | 首期落地仓只按建筑形态区分，层高决定货架与库位高度 |

### 2026-11-24 部署形态从仓内单机改为云上独立实例

| 原设计 | 修正为 | 触发原因 |
|---|---|---|
| Site 部署在仓内单机容器，仓内网作为网络边界 | 每仓一套独立云上实例，云区域与仓同城；网络边界改为公网接入 + 设备白名单 | 实际部署全部在云服务上，仓内不设机房 |

### 2026-11-24 移动作业端从小范围 PDA 扩到普通安卓手机

| 原设计 | 修正为 | 触发原因 |
|---|---|---|
| 原生 App 只面向工业 PDA，手机不在范围内 | 同一套 App 覆盖工业 PDA 与普通安卓手机，扫码通道按设备能力选（D58） | 现场终端不只 PDA，手机也要能直接作业 |

# 术语与枚举登记表

## 1 结论

全库每个业务词只有一个释义、每个枚举只有一处登记；登记必须同时给出分类维度、完整取值、权威文档、互斥证明与穷尽证明，五项缺一即视为未登记。v1 的 13 条枚举失守缺陷，根因就是各文档按自己的口径分档计数而没有登记处。

## 2 问题与范围

**解决**：有哪些取值、按什么维度分、谁说了算、是否相互独立且完全穷尽。

**不解决**：取值怎么用（卷二业务文档）、状态怎么推进（`22`）、界面尺寸与样式（卷四）。

## 3 设计

### 3.1 统一词表（最易混淆的十二个词）

一个业务词一个释义，跨上下文同词不同义时分行标注，禁止另造别名。

| 词 | 本版释义 | 易混淆点 |
|---|---|---|
| 货主 | 唯一隔离维度，所有货主同构 | 不是租户；自营业务也是普通货主 |
| 仓 | 一套独立部署与独立库的作业主体 | 不等于建筑；楼层不是一级对象 |
| 库区 | 仓内按温区、用途划分的空间 | 温区挂在库区上，不是仓库单值 |
| 库位 | 有四段物理坐标的真实位置，库存唯一锚点 | 不存在虚拟库位；容器不是位置 |
| 容器 | 装载单元，可挂库存，但位置由库位决定 | 不是库位，不能承载位置语义 |
| 库存 | 按七字段唯一键记在真实库位上的在库量 | 只有两个数量字段，冻结靠状态行 |
| 作业事实 | 单仓端产生、供计费域消费的作业记录 | 不是单据状态，不含金额 |
| 单据 | 两族共用单头单行的履约或作业凭证 | 不产生费用；进度不进状态 |
| 波次 | 产能调度单元，是实体不是明细行属性 | 不等于拣货合并 |
| 任务 | 由单据产生、携带锁定切片的执行单位 | 与设备任务分离 |
| 班组 | 仓内作业组织，最多三层 | 不是权限组织，不进数据域 |
| 角色 | 带端标识的功能集合 | 班组长是职务不是角色 |

### 3.3 新增取值或新增枚举的四道检查

按顺序全过才算登记完成，任一道不过即退回。

1. **维度单一**：本类所有取值是否按同一个维度切出；混入第二维度即拆成两类。
2. **取值不重叠**：任取两个取值，是否存在一个对象同时落入两者；存在即重切。
3. **全集闭合**：写出维度的取值域，逐项对照取值列；确有兜底项时必须写明触发条件，「其他」二字不算条件。
4. **权威源唯一**：每类只能有一个权威文档；其余文档只能引用编号，不得自行扩写取值。

检查方法见 `../review/R4-验证说明.md` 第 1.2 节。

## 4 约束与验证

| 检查项 | 判定方法 |
|---|---|
| 登记完整 | 十二类逐行五要素齐全，无空格 |
| 待定可见 | 标注待拍板或已落实的行，在 `23` 待定项或 `index.md` 迁入清单中有对应条目 |
| 无第二登记处 | 全库检索同一枚举的完整取值清单，应只在本文出现一次 |
| 跨文档一致 | 端、模块、可启动单元、库存状态、状态机五类须与 `index.md`、`22` 表述一致 |
| 兜底合规 | 任何「其他」都附判定条件，否则不算穷尽 |

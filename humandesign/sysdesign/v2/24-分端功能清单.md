# 分端功能清单

## 1 结论

四端功能清单以本文件为唯一登记处：一条功能项必须同时给出端、页面骨架、权限点模块、归属单元四项，缺一项即不算登记；同一业务只允许一个写入入口，其余端只能是只读视图；端与单元不是一对一，一个端可以调用多个可启动单元。

## 2 问题与范围

**解决**：哪个端有哪些功能入口、每项落在哪类页面骨架、需要哪个模块的权限点、调哪个可启动单元、由哪个角色使用。

**不解决**：视觉与交互细节（见 `12`、`12a`、`12b`）；路由、接口映射与按钮级权限点编码（见变更的前端设计章与 `19`）；数据库表结构（见 `11`）；排期与批次（属计划，不进设计）。

## 3 设计

### 3.1 一条功能项由四项要素与两项附属构成

| 项 | 取值要求 | 依据 |
|---|---|---|
| 端 | 运营端、货主端、单仓端、移动作业端之一 | `21` E-01 |
| 功能项 | 动宾短语，一条只做一件事；含"与"的拆成两条 | 本文件 |
| 页面骨架 | Web 取 `UI-P01`、`UI-P02`、`UI-P03`、`UI-P09`、`UI-P10`；移动取 `UI-M14` 至 `UI-M17` | `12a`、`12b` |
| 权限点模块 | `M01` 至 `M11` 之一定位模块，加动作词；编码由代码声明，本文件不写编码 | `05`、`19` |
| 归属单元 | 运营端、单仓端、公网接入层、计费域之一 | `21` E-02 |
| 使用者角色 | 必须是 `05` 已登记的角色 | `05` |

### 3.2 同一业务只允许一个写入入口

同一业务对象可以出现在多个端，但只有一处是入口，其余是只读视图。多端同时可写，等于同一份数据有两个真值来源。

| 业务对象 | 唯一入口 | 只读视图 |
|---|---|---|
| 单据 | 单仓端（受理、执行）与运营端（调拨单）按单据族分 | 运营端看聚合副本、货主端看本货主单据 |
| 库存 | 单仓端 | 运营端看副本、货主端看库区粒度汇总 |
| 任务 | 单仓端（指派）与移动作业端（执行）按动作分 | 运营端不展示任务 |
| 合同与账单 | 计费域（运营端页面录入） | 货主端看本货主账单 |
| 主数据 | 运营端 | 单仓端读缓存，作业不实时反查 |

|---|---|---|---|---|
| 库存查询（到库区） | `UI-P01` + `UI-P02` | 副本查询 | 公网接入层 | 货主用户 |
| 单据查询与确认 | `UI-P01` + `UI-P02` | M05 单据只读与确认 | 公网接入层 | 货主用户 |

### 3.7 一个端可以调用多个单元

| 端 | 可调单元 | 不调 |
|---|---|---|
| 运营端 | 运营端单元、计费域 | 单仓端单元、公网接入单元 |
| 单仓端 | 单仓端单元，读运营端主数据缓存与合同生效状态 | 计费域的算费与出账接口 |
| 货主端 | 公网接入单元 | 直连单仓端与计费域 |
| 移动作业端 | 单仓端单元 | 运营端、计费域、公网接入单元 |

合同数据在计费域、页面在运营端，是本表最容易配错的一处：页面归属看使用者，接口归属看数据权威源，两者不能混为一谈。

## 4 约束与验证

| 检查项 | 判定方法 |
|---|---|
| 四项齐全 | 逐条功能项的端、骨架、权限点模块、归属单元均无空格 |
| 骨架合法 | 页面骨架编号只能取 `12a` 与 `12b` 已登记值，出现第六类即失败 |
| 一端一入口 | 同一业务在多端出现时，表中只有一处置为入口，其余标注只读 |
| 权限点不新造 | 只写 `M01` 至 `M11` 加动作词；编码以代码声明为准，见 `19` |
| 单元可达 | 归属单元只取四个可启动单元，见 `21` E-02 |
| 角色存在 | 使用者角色在 `05` 中可查，未登记角色不得出现在本表 |

**强制手段**：新增页面或新增接口前先查本表，表中无登记不予评审；本表与 `12a`、`12b`、`05`、`19` 逐项对账，任一处不一致以本表为入口清单、以被引文档为规则源分别修正。

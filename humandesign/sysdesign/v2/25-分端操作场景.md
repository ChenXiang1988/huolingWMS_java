# 分端操作场景

## 1 结论

每个流程类场景必须同时给出正向、逆向、异常、重复提交四条路径；逆向不与异常混为一类，单独成章并按撤销深度分五组；每条逆向必须写明不可逆点与对账手段，没有不可逆点的逆向视为未设计。

## 2 问题与范围

**解决**：谁在什么状态下按什么顺序完成一件业务、往回走时连带撤销什么、走不通时分流到哪、重复发起时靠什么去重。

**不解决**：页面字段与校验（见 `12`、`12a`、`12b`）；接口契约与错误码（见变更的 API 接口契约章）；状态词与事务例外本身（只引用 `22` 的 `S-xx`、`T-xx`）；权限点编码（见 `19`）。

## 3 设计

### 3.1 一条场景登记六个要素

| 要素 | 要求 |
|---|---|
| 触发条件 | 谁、在什么状态下可以发起，前置状态必须引用 `22` 的状态编号 |
| 步骤 | 三到七步，超过七步拆成两条场景 |
| 连带动作 | 本场景会不会引发别的对象变化；跨聚合同事务只引用 `T-01` 至 `T-05` |
| 不可逆点 | 走到哪一步之后不能回头；终态无后继 |
| 对账手段 | 怎么发现"该做的没做、该撤的没撤" |
| 幂等键 | 重复发起、重试、消息重投时靠什么去重 |

### 3.2 正向场景按业务链排列

正向按"端加业务链"分组，一条链路一条场景，不按页面拆。

| 编号 | 场景 | 步骤要点 | 涉及页面 | 终态 |
|---|---|---|---|---|
| 场正-01 | 货主开通 | 建档案 → 绑合同 → 开账号 → 对全仓网可见 | 运营端货主管理 | 货主可用 |
| 场正-02 | 仓装配 | 建档案 → 填法域与仓型 → 勾能力矩阵 → 配日历 → 提交 | 运营端仓网管理 | 仓进入拟定 |
| 场正-03 | 仓部署与生效 | 部署绑定 → 已部署 → 库位与日历齐备 → 生效 | 运营端仓网管理 | 仓进入生效 |
| 场正-04 | 角色授权 | 建角色 → 配权限点与数据域 → 分配账号 | 运营端权限配置 | 账号持角色 |
| 场正-05 | 合同生效 | 建合同 → 配费率卡 → 定版本生效日 → 生效 | 运营端合同维护 | 合同可作业 |
| 场正-06 | 开仓初始化 | 建库区 → 建库位并录四段坐标 → 设容量 → 启用库位 | 单仓端库位配置 | 库位可存放 |
| 场正-07 | 入库受理到上架 | 受理 → 生成收货任务 → 收货 → 质检 → 上架 → 入账 | 单仓端单据、移动作业端执行 | 库存增加 |
| 场正-08 | 出库受理到发运 | 受理 → 等待池 → 成波 → 释放到现场 → 拣货 → 复核 → 发运 | 单仓端波次、移动作业端执行 | 库存减少 |
| 场正-09 | 盘点 | 生成盘点单 → 下发任务 → 扫码盘点 → 差异确认 → 差异关闭 | 单仓端盘点、移动作业端执行 | 账实一致 |
| 场正-10 | 移库 | 发起移库单 → 生成任务 → 执行 → 库存位移 | 单仓端移库、移动作业端执行 | 位置变更 |
| 场正-11 | 班组与派工 | 建班组 → 归人 → 任免班组长 → 任务指派 | 单仓端班组 | 任务到人 |
| 场正-12 | 货主查库存 | 登录 → 按库区查 → 导出 | 货主端库存查询 | 只读 |
| 场正-13 | 货主入库预约 | 填预约 → 提交 → 单仓端受理 | 货主端预约单 | 预约待受理 |
| 场正-14 | 货主查账单 | 登录 → 账单列表 → 详情 → 打印 | 货主端账单查询 | 只读 |
| 场正-15 | 登录与接任务 | 员工码加识别码 → 任务列表 → 接任务 | 移动作业端登录、列表 | 任务进行中 |
| 场正-16 | 扫码执行 | 扫库位 → 扫商品 → 扫批次 → 输数量 → 提交 | 移动作业端任务执行 | 任务完成 |
| 场正-17 | 异常上报 | 选类型 → 填说明 → 提交 → 返回任务 | 移动作业端异常页 | 异常待处理 |
| 场正-18 | 换班退登 | 结束当前任务 → 退登 → 下一位登录 | 移动作业端登录 | 会话结束 |

复核不新增任务类型，按作业要求项执行；分工流水模式下复核人不得与拣货人同一人，这条落在人员约束上，不落在页面上。

### 3.3 逆向场景单独成章，按撤销深度分五组

分组依据是撤销的影响半径：越往后越不可逆，补偿成本越高。正向按业务链排，逆向按撤销对象排，两者分类维度不同，所以不并入同一节。

**第一组 主数据：可恢复**

| 编号 | 场景 | 触发与前置 | 连带动作 | 不可逆点 | 对账手段 |
|---|---|---|---|---|---|
| 场逆-01 | 货主停用 | 主数据管理员，货主为可用 | 阻断新建业务，不阻断存量单据走完 | 停用不自动恢复，重开需留痕 | 扫描停用货主是否仍有新建单据 |
| 场逆-02 | 仓停用 | 仓网管理员，仓为生效 | 阻断新单受理，存量任务可结案 | 库存不为零不得进入归档 | 日结扫描停用仓的在途任务 |
| 场逆-03 | 仓归档 | 仓为停用且库存为零 | 无 | 归档是终态，无后继转换 | 归档清单与部署清单对账 |
| 场逆-04 | 角色回收与账号停用 | 权限管理员 | 权限即时失效，缓存版本递增 | 历史操作留痕不删除 | 越权用例加缓存版本核对 |

**第二组 单据：可重做**

| 编号 | 场景 | 触发与前置 | 连带动作 | 不可逆点 | 对账手段 |
|---|---|---|---|---|---|
| 场逆-05 | 单据取消（未执行） | 单据为已受理，且无进行中任务 | 回等待池，释放占用 | 已有作业事实的单据取消是否冲销，依 `23` 决二 | 扫描已取消但仍有任务引用的单据 |
| 场逆-06 | 差异关闭 | 单据为执行中且差异已登记 | 关闭差异，单据转终态 | 差异关闭后不可再推进 | 差异清单与库存流水对账 |

**第三组 任务与波次：需补偿释放**

| 编号 | 场景 | 触发与前置 | 连带动作 | 不可逆点 | 对账手段 |
|---|---|---|---|---|---|
| 场逆-07 | 任务取消 | 任务为已指派或执行中 | 释放锁定，见 `T-02` | 取消后不释放锁定即违规 | 日结扫描已取消但锁定未释放 |
| 场逆-08 | 波次取消 | 波次为新建、已释放或执行中 | 释放资源、释放锁定、单据回等待池，三者同一事务，见 `T-03` | 已发运不可取消 | 扫描已取消波次是否仍有绑定资源 |
| 场逆-09 | 任务改派 | 任务为已指派未开始 | 释放原指派，重新绑定执行人 | 已开始的协作任务不拆片 | 分片之和等于父任务分配量 |

**第四组 库存：需反向记录**

| 编号 | 场景 | 触发与前置 | 连带动作 | 不可逆点 | 对账手段 |
|---|---|---|---|---|---|
| 场逆-10 | 冻结与解冻 | 单仓管理者，目标库存行存在 | 只改状态不搬货 | 冻结期间不可分配 | 冻结行是否出现在分配结果中 |
| 场逆-11 | 移库回退 | 移库已完成 | 补一条反向流水，不改原流水 | 原流水不可改删 | 流水条数与移库单数比对 |
| 场逆-12 | 盘点差异调整 | 盘点差异已确认 | 补调整流水，不改原流水 | 原流水不可改删 | 差异清单与调整流水逐条对上 |
| 场逆-13 | 退货入库 | 原出库已完成 | 新建退货单据入账，不反冲原出库 | 原出库单据与流水的统计口径不变 | 退货单与原出库单关联核对 |

**第五组 金额：只能反向，永不可逆**

| 编号 | 场景 | 触发与前置 | 连带动作 | 不可逆点 | 对账手段 |
|---|---|---|---|---|---|
| 场逆-14 | 计费明细冲正 | 计费专员，原明细存在 | 反向明细加新增明细，原明细不动 | 原明细不可修改与删除 | 冲正明细与原明细金额相加为零 |
| 场逆-15 | 合同失效 | 计费专员，合同为生效 | 阻断新作业，已发生事实按原版本计费 | 已发生事实不追改 | 事实发生日与合同版本区间比对 |
| 场逆-16 | 账单重算 | 对账员 | 以事实为准重算，产出新账单 | 已出账单不做修改，只出新版本 | 账单版本与事实条数对账 |

### 3.4 异常按触发环节分流，不与逆向混为一类

异常是执行中的偏离，不是业务回退。异常必须给出唯一出口，出口要么回到原流程，要么转成逆向动作，不得悬空。

| 编号 | 触发环节 | 典型情况 | 出口 |
|---|---|---|---|
| 场异-01 | 扫码 | 码损、错扫、扫到非本任务的商品 | 重扫；连续失败转手工录入并留痕 |
| 场异-02 | 数量与包装 | 数量短缺、包装破损 | 登记差异，转异常处理，必要时走场逆-06 |
| 场异-03 | 网络 | 请求超时、漫游抖动 | 重试与幂等提交，不做离线队列 |
| 场异-04 | 状态冲突 | 单据已被他人处理、任务已被改派 | 刷新后重试，不覆盖他人结果 |
| 场异-05 | 外部服务 | 关务与物流结果未回 | 落观察区，不推进状态，不重试到阻塞作业 |
| 场异-06 | 设备 | 摄像头被占用、扫码头故障、非登记设备 | 切手工录入或换设备，非登记设备拒绝登录 |

场异-05 的边界：外部结果只作观察字段，不参与状态转换；本系统不发起申报、不跟踪运输、不判断清关结论。

### 3.5 重复提交与幂等单独登记

| 编号 | 情形 | 幂等键 | 预期表现 |
|---|---|---|---|
| 场幂-01 | 同一作业重复提交 | 任务号加操作序号 | 第二次返回首次结果，不产生第二条流水 |
| 场幂-02 | 消息重投与重复消费 | 事件编号 | 消费端按编号去重，重复消费不重复记账 |
| 场幂-03 | 断网重试与补传 | 请求号 | 服务端按请求号识别重放，不重复扣减 |

幂等做在入口，依据 `00` D21；三个键都必须在接口契约里出现，缺一即为未设计。

## 4 约束与验证

| 检查项 | 判定方法 |
|---|---|
| 四路径齐全 | 每条正向场景都能指到对应的逆向、异常与幂等条目，指不到即为缺口 |
| 逆向不混异常 | 逆向章内不出现"失败""重试"类描述，异常章内不出现"取消""退回"类动作 |
| 状态可解析 | 场景中的状态词全部能在 `22` 找到，禁止另造 |
| 事务有依据 | 跨聚合的连带动作只引用 `T-01` 至 `T-05`，不自行声明例外 |
| 不可逆点必填 | 每条逆向的不可逆点列不得为空，空即视为未设计 |
| 对账可执行 | 对账手段必须能落到一条查询或定时任务，不写"人工检查" |
| 幂等键落地 | 幂等键在接口契约中可查，缺项即失败 |

**强制手段**：本文件与 `22` 的状态与事务总表逐条对账；新增流程类需求时先在本表登记四路径，未登记不进入设计与评审。

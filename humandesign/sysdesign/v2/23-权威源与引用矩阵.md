# 权威源与引用矩阵

## 1 结论

任何规则都能在本文件查到唯一定义处，任何编号都能查到唯一对象，任何未决事项都能查到状态。v1 的 19 条权威源冲突与 4 条引用断链，根因是没有这张表：`00` 停在被推翻的旧结论上，下游各自演进，`log` 记了修订却没人同步总纲。

## 2 问题与范围

**解决**：这条规则谁说了算、编号指向什么、引用怎么校验、还有哪些没定、各文档现在是什么状态。

**不解决**：不产生任何新的业务结论；规则的正文仍在各自的定义文档里。

## 3 设计

### 3.1 权威源矩阵

「定义处」是唯一可修改的位置；「可引用处」只能引用，不得改写结论。冲突处理顺序固定为：`00` 决策 → `00a` 红线与不变量 → `15` 边界 → 领域文档 → 落地文档 → 界面文档。低层不得推翻高层；确需推翻时先改高层、记入 `log.md`，再逐层同步。

| 规则类别 | 定义处 | 可引用处 | 冲突时的处理 |
|---|---|---|---|
| 已定决策、被否决方案 | `00` | 全库 | 先改 `00`，再逐层同步 |
| 红线、全局不变量、强制手段 | `00a` | 全库 | 以 `00a` 为准，`04`、`11` 不得另写一套 |
| 限界上下文、词表归属、公开事件、跨境边界 | `15` | 卷二、卷五、卷四 | 边界优先于实现 |
| 枚举取值、统一词表 | `21` | 全库 | 未登记的取值不成立 |
| 状态词、转换、事务例外、锁定链 | `22` | 全库 | 业务文档不得另造状态词 |
| 编号对照、引用校验、待定项、文档状态 | `23`（本文件） | 全库 | 本文件是状态的唯一定义处 |
| 模块与表的独占关系 | `03` | `11`、`14` | 模块清单以 `03` 为准 |
| 建表语句、事务实现、并发手段 | `11` | 卷二、卷五 | 不得与 `00a`、`22` 冲突 |
| 构建期断言 | `14` | 卷五 | 一码一义，`AR-xx` 只在此定义 |
| 界面令牌、组件、文案、页面骨架 | `12`、`12a`、`12b` | 卷四内部 | 同一前缀只归一份文档 |
| 角色、鉴权链路、班组与人员 | `19`、`05`、`20` | 卷三内部 | 缓存机制只在 `19` 定义 |
| 各业务对象的动作与异常 | 卷二各文档 | 卷四、卷五 | 不得改写卷一结论 |
| 版本状态与升级方法 | `../版本规则.md`、各版 `index.md` | 全库 | 常驻规则不随版本归档 |

### 3.3 引用校验规则

按顺序执行，任一条不过即视为该文档未完成。

1. **编号存在**：引用的每个编号都能在 3.2 表中查到权威文档，且该文档在当前版本目录内。
2. **语义相符**：编号指向的对象与引用语境一致；出现「指向存在的编号但语义不对」即错指。
3. **清单闭合**：每份文档第 5 章「引用与权威源」的汇总清单与正文逐条相符，无漏列、无悬空列。
4. **主从分明**：结论只在定义处出现一次，其余位置为引用句；同一规则出现两套完整表述即失败。
5. **历史标注**：引用 `../v1/` 时必须写明「历史版本 v1，仅供溯源」，且不得用其推翻当前结论。
6. **重号即失败**：全库扫描编号唯一；新增编号先查本表再使用。

31 份文档已全部落盘。「编号存在、清单闭合、重号扫描」三项自动检查尚未接入，已登记 3.4 节待定项；本轮只登记规则，不编写脚本、不改动检查配置。

## 4 约束与验证

| 检查项 | 判定方法 |
|---|---|
| 权威唯一 | 逐条规则只有一个定义处；全库检索同规则的完整表述应为一次 |
| 编号可解析 | 3.2 表每个编号族都有权威文档，且文档存在于当前版本目录 |
| 引用闭合 | 按 3.3 六条逐份扫描，重号、悬空、错指为零 |
| 待定唯一 | 本表 23 项之外的待定表为零命中；拍板项已销项 |
| 状态一致 | 本表与 `index.md`、`log.md` 三处状态一致 |
| 冲突顺序可执行 | 出现分歧时能按 3.1 的顺序唯一裁定 |

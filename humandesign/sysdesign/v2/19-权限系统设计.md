# 权限系统设计

## 1 结论

权限系统由功能权限、数据域、会话固定域三部分构成；鉴权全部在服务端完成，权限变更即时生效，权限数据由 Hub 权威、Site 缓存。

## 3 设计

### 一次请求过四道门

| 顺序 | 判定 | 失败返回 |
|---|---|---|
| 一 | 令牌有效，端与设备匹配 | 401 |
| 二 | 接口声明的权限点在角色权限集内 | 403 |
| 三 | 会话固定域与配置域算出非空数据域 | 403 |
| 四 | 仓储层按数据域注入查询条件 | — |

四道门缺一不可。只做前两道是「能进门但能看全部数据」，只做后两道是「看不到但什么都能改」。

### 七张表，权限点不在其中新建

| 表 | 存什么 | 写入方 |
|---|---|---|
| `account` | 账号、所属货主（货主端账号）、`employee_id`、状态 | M01；单仓端受限开通现场作业员账号 |
| `role` | 角色名、`applies_to_client`（端标识）、状态 | M01 |
| `permission` | 权限点编码、所属模块、状态 | 构建期从代码同步，只读 |
| `role_permission` | 角色与权限点关联 | 权限管理员 |
| `account_role` | 账号与角色关联，落端 | 权限管理员；单仓端受限授予现场作业员与单仓管理者 |
| `role_scope` | 角色的数据域规则：维度、范围类型 | 权限管理员 |
| `role_scope_item` | 范围类型为「指定列表」时的具体标识 | 权限管理员 |

三个字段决定隔离边界：

| 字段 | 取值 | 作用 |
|---|---|---|
| `role.applies_to_client` | 运营端 / 单仓端 / 作业端 / 货主端 | 登录时按端过滤角色，不跨端合并 |
| `role_scope.dimension` | 货主 / 仓 | 数据域维度，白名单外一律拒绝 |
| `role_scope.scope_type` | 全部 / 指定列表 | 指定列表时由 `role_scope_item` 提供标识 |

范围不用 JSONB 存：用了就没法加外键，货主或仓被停用后还能留在授权列表里，谁也发现不了。

员工账号与员工一对一：`account.employee_id` 唯一，货主端账号该列为空。账号开通与停用由单仓端发起，落库仍写 Hub 的权限库。

### 权限点由代码声明，启动时同步

接口上以注解声明所需权限点，启动时扫描全部映射，与 `permission` 表双向对账：

| 情况 | 处理 |
|---|---|
| 代码有、表里没有 | 插入 |
| 代码没有、表里有 | 置为停用，不物理删除（INV-18） |
| 接口未声明权限点且不在白名单 | 启动失败 |

最后一条是防线：新增接口忘了声明权限点，宁可起不来，也不能默认放行。白名单只留登录、健康检查、契约导出三类。

### 权限集缓存在服务端，用全局版本号失效

| 项 | 做法 |
|---|---|
| 键 | 账号 ID + 端 + 全局权限版本号 |
| 值 | 权限点集合 + 已算好的数据域 |
| 有效期 | 30 分钟兜底 |
| 失效 | 任何授权动作使全局版本号加一，旧键自然不再命中 |

不用「按角色反查在线账号再逐个删键」：那需要维护角色到账号的反向索引，还要处理并发删除。权限变更一天不过几次，全员重建一次缓存的代价远小于这套复杂度。

代价要认：改一个人权限会让所有人下次请求多查一次库。

### 数据域合并规则在服务端算一次，不逐条查询算

| 情形 | 合并方式 |
|---|---|
| 同维度多条 | 并集 |
| 跨维度 | 交集 |
| 任一维度为空 | 拒绝 |

合并结果随权限集一起缓存，请求期只做注入不做计算。

### 仓储层注入，参数不得覆盖会话域

| 数据域 | 注入方式 |
|---|---|
| 仓域为指定列表 | `warehouse_id IN (...)` |
| 仓域为全部 | 不加仓条件 |
| 货主域为指定列表 | `owner_id IN (...)` |
| 货主域为全部 | 不加货主条件 |

请求体或查询参数里出现货主、仓的标识时，与会话域比对，不一致直接 403。允许客户端传标识但不允许它扩大范围——这条比「忽略参数」更严，因为忽略会让人以为传了有效。

### 三个端的固定域在登录时写入会话

| 端 | 会话内固定 | 是否可被配置覆盖 |
|---|---|---|
| 运营端 | 端标识 | 否 |
| 单仓端 | 端标识 + 仓 | 否 |
| 作业端 | 端标识 + 仓 + 设备 | 否 |
| 货主端 | 端标识 + 货主 | 否 |

固定域先于配置域参与合并，且配置域不能把范围扩大到固定域之外。货主端账号即使被误配了「货主域：全部」，合并结果仍是本货主。

### Site 侧权限是副本，落后时分级降级

| 缓存状态 | 管理类操作 | 作业类操作 |
|---|---|---|
| 版本一致 | 放行 | 放行 |
| 落后未超阈值 | 放行 | 放行 |
| 落后超过阈值 | 拒绝 | 放行 |

阈值按仓定，默认 24 小时。现场停摆的代价大于权限短暂陈旧，但管理类操作涉及配置与授权，不能拿旧权限放行。

### 单仓端只能授本仓作业与管理角色

员工在当地招聘，账号与角色由单仓端开通，但授权范围必须收死，否则单仓端就成了提权入口。

| 项 | 规定 |
|---|---|
| 可创建账号 | 只限本仓员工，`employee_id` 非空 |
| 可授予角色 | 现场作业员、单仓管理者；端为单仓端与作业端 |
| 数据域 | 固定本仓，由会话固定域收口，不写 `role_scope` |
| 不能授予 | 计费专员、对账员、跨仓调度员、权限管理员 |
| 不能操作 | 不能给自己开账号、授角色、停账号 |
| 管理者数量 | 至少保留一个可用单仓管理者；免职或停用最后一个拒绝 |
| 失败 | 越权返回 403，写操作日志 |

| 边界 | 内容 |
|---|---|
| 角色白名单在代码里 | 不在库里配；新增角色不会自动进入单仓端可授予范围 |
| 账号必须绑定本仓员工 | `employee_id` 与会话仓不一致直接拒绝 |
| 离职停本仓账号 | 现场作业员与单仓管理者账号都停；权限管理员账号归运营端 |
| 授权动作照样留痕 | 谁、给谁、开了什么、何时，写入操作日志 |

### 异常一律拒绝，不猜

| 场景 | 返回 |
|---|---|
| 无权限点 | 403，不说明资源是否存在 |
| 数据域为空 | 403 |
| 令牌过期 | 401 |
| 设备未绑定或已吊销 | 401，提示重新激活 |
| 权限缓存不可用且查库失败 | 503，不放行 |

缓存不可用时降级查库，查不到就拒绝。任何「取不到权限就按默认放行」的写法都是漏洞。

### 授权与初始化

| 动作 | 规则 |
|---|---|
| 授权 | 操作者不能等于目标账号；每次授权写操作日志，记录变更前后 |
| 角色初始化 | 脚本随代码版本走，按端建角色，不手工建 |
| 权限点初始化 | 启动同步，见上 |
| 账号初始化 | 单仓端开通作业账号默认现场作业员；单仓管理者由单仓端或权限管理员授，不预置其他角色 |

## 4 约束与验证

| 约束 | 强制手段 |
|---|---|
| 未声明权限点的接口不得放行 | 启动检查：扫描全部映射，白名单外未声明的直接启动失败 |
| 单仓端不能授全局治理角色 | 应用校验：角色白名单；白名单外 403 |
| 至少保留一个单仓管理者 | 应用校验：免职前校验数量；为零拒绝 |
| 角色不跨端合并 | 应用校验：登录时按 `applies_to_client` 过滤；跨端叠加用例 |
| 数据域为空不得放行 | 应用校验：合并结果为空返回 403 |
| 参数不得扩大会话域 | 应用校验：请求标识与会话域比对，不一致 403 |
| 货主端域不可被配置放宽 | 应用校验：合并时固定域收口，配置域只能缩小 |
| 权限变更即时生效 | 应用校验：授权后全局版本号加一；用例覆盖权限回收 |
| 权限点表不得手工新增 | 数据库权限：`permission` 表对应用账号只授读 |
| 缓存故障不得默认放行 | 代码评审 + 故障演练：缓存不可用时返回 503 |

引用的决策编号：D12、D23、D40、D39、D62；不变量：INV-06、INV-19。角色清单与模块矩阵见 05，表结构细节并入 11。

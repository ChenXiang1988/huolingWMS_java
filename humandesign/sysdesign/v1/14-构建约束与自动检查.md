# 构建约束与自动检查

全部架构约束由 ArchUnit 在构建期断言，任一失败阻断合并；人工评审不承担守门职责。

---

## 问题

**解决**：把 00 与 03 定下的依赖、分层、聚合根、事件发布规则，变成可执行的断言，并给出写法。

**不解决**：业务逻辑是否正确、并发是否安全、数据是否对账——这些靠单元测试、集成测试与日结核对，不靠架构断言。

**边界**：本文只写"怎么检查"，不重复"应该是什么"；规则内容见 00 与 03。

---

## 设计

### 依赖方向用分层规则一次断言

四条分层规则写在同一个测试类里，覆盖所有模块，不需要逐模块写：

```java
@AnalyzeClasses(packages = "com.huoling.wms", importOptions = ImportOption.DoNotIncludeTests.class)
class LayeringRulesTest {

    @ArchTest
    static final ArchRule 分层只能单向 =
        ArchRuleDefinition.classes()
            .that().resideInAPackage("..domain..")
            .should().onlyBeAccessed().byAnyPackage("..domain..", "..application..", "..infrastructure..");

    @ArchTest
    static final ArchRule 领域层不依赖框架 =
        ArchRuleDefinition.noClasses()
            .that().resideInAPackage("..domain..")
            .should().dependOnClassesThat().resideInAnyPackage(
                "org.springframework..", "org.apache.ibatis..", "jakarta.persistence..",
                "com.baomidou..", "org.redisson..", "org.springframework.amqp..");

    @ArchTest
    static final ArchRule 应用层不得被基础设施层反向依赖 =
        ArchRuleDefinition.noClasses()
            .that().resideInAPackage("..infrastructure..")
            .should().dependOnClassesThat().resideInAPackage("..application..");

    @ArchTest
    static final ArchRule 启动单元之间互不依赖 =
        ArchRuleDefinition.noClasses()
            .that().resideInAPackage("..hub..")
            .should().dependOnClassesThat().resideInAnyPackage("..site..", "..open..", "..billing..");
}
```

四条断言各管一件事：方向、框架污染、反向依赖、单元隔离。`..billing..` 同理再补三条（site、open、hub 各一条），共六条。

### 聚合根的约束用注解加自定义断言表达

先定义注解，放在 `wms-common`：

```java
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
public @interface AggregateRoot {
}
```

**规则一：聚合根不暴露 setter。**

```java
@ArchTest
static final ArchRule 聚合根不暴露 setter =
    ArchRuleDefinition.methods()
        .that().arePublic()
        .and().areDeclaredInClassesThat().areAnnotatedWith(AggregateRoot.class)
        .should().notHaveNameMatching("set[A-Z].*");
```

这条能抓住"给聚合根加了 setter"这一类，是防贫血模型的第一道。

**规则二：聚合根必须有行为。**

```java
@ArchTest
static final ArchRule 聚合根必须有行为 =
    ArchRuleDefinition.classes()
        .that().areAnnotatedWith(AggregateRoot.class)
        .should(至少有一个业务方法());

static ArchCondition<JavaClass> 至少有一个业务方法() {
    return new ArchCondition<>("除访问器外至少有一个业务方法") {
        @Override
        public void check(JavaClass item, ConditionEvents events) {
            boolean hasBehavior = item.getMethods().stream()
                .filter(m -> m.getModifiers().contains(JavaModifier.PUBLIC))
                .anyMatch(m -> !isAccessor(m) && !isObjectMethod(m));
            if (!hasBehavior) {
                events.add(SimpleConditionEvent.violated(item,
                    item.getName() + " 只有访问器，没有业务方法"));
            }
        }

        private boolean isAccessor(JavaMethod m) {
            return m.getName().startsWith("get") || m.getName().startsWith("is");
        }

        private boolean isObjectMethod(JavaMethod m) {
            return Set.of("equals", "hashCode", "toString").contains(m.getName());
        }
    };
}
```

**规则三：状态字段只能由聚合根自己改。**

字段级访问 ArchUnit 不支持直接断言，改用两条近似：状态字段必须 `private`、且类型为枚举。

```java
@ArchTest
static final ArchRule 状态字段必须是私有枚举 =
    ArchRuleDefinition.fields()
        .that().haveNameMatching(".*[Ss]tatus")
        .and().areDeclaredInClassesThat().areAnnotatedWith(AggregateRoot.class)
        .should().bePrivate()
        .andShould().haveRawType(Enum.class);
```

三层加起来覆盖"改不了、必须自己改、改的时候有约束"。

### 值对象不可变

```java
@ArchTest
static final ArchRule 值对象不可变 =
    ArchRuleDefinition.fields()
        .that().areDeclaredInClassesThat().areAnnotatedWith(ValueObject.class)
        .should().beFinal()
        .andShould().bePrivate();
```

配合"聚合根无 setter"使用。值对象的构造器校验无法用架构规则表达，只能靠单元测试。

### 领域事件只能由领域包发布

```java
@ArchTest
static final ArchRule 事件只能由领域层发布 =
    ArchRuleDefinition.noClasses()
        .that().resideOutsideOfPackage("..domain..")
        .should().callMethodWhere(
            target().isDeclaredInClassesThat().haveSimpleName("DomainEventPublisher"));
```

前提是把发布入口收进 `domain` 包并设为包级可见；否则应用层能直接调，这条断言就失效。

### 跨模块只传 DTO

每个模块的 domain 包都对其他模块不可见，逐模块生成断言的写法：

```java
@ArchTest
static final ArchRule 订单模块不暴露领域实体 =
    ArchRuleDefinition.noClasses()
        .that().resideOutsideOfPackage("..order..")
        .should().dependOnClassesThat().resideInAPackage("..order.domain..");
```

十一个模块各写一条，用循环生成也可以：

```java
@ArchTest
static final ArchTests 模块边界 = (() -> {
    ArchTests suite = new ArchTests() {
        @Override
        public void addTo(ArchTests tests) { }
    };
    for (String m : List.of("warehouse", "location", "stock", "task", "order",
                            "strategy", "processing", "billingfact", "device", "team")) {
        tests.add(ArchTests.of("模块 " + m).add(
            ArchRuleDefinition.noClasses()
                .that().resideOutsideOfPackage(".." + m + "..")
                .should().dependOnClassesThat().resideInAPackage(".." + m + ".domain..")));
    }
    return suite;
});
```

### 仓型硬编码用 CI 扫描，不用架构断言

`if (warehouseType == 楼层仓)` 这类分支无法用包依赖表达，因为策略实现合法地需要读仓型。改用构建脚本扫描：

```bash
if grep -rEn '==\s*WarehouseType\.|==\s*仓型\.' --include='*.java' \
   backend/*/src/main/java | grep -v '/strategy/'; then
  echo "仓型比较只允许出现在 strategy 包"; exit 1;
fi
```

放行条件是文件路径含 `/strategy/`，其余位置出现即失败。

### 规则清单与失败表现

| 编号 | 断言 | 失败时说明什么 |
|---|---|---|
| AR-01 | 分层只能单向 | 有人在 domain 里调 application，或 infra 反向依赖应用层 |
| AR-02 | domain 不依赖框架 | 有人在实体上加了 `@Entity` 或 `@TableName`，或注入 Spring 组件 |
| AR-03 | 启动单元互不依赖 | 有人让 hub 直接引用了 site 的类 |
| AR-04 | 聚合根无 setter | 有人用 `@Data` 或 `@Setter` 生成访问器，模型开始贫血 |
| AR-05 | 聚合根有行为 | 只建了数据类，没有业务方法 |
| AR-06 | 状态字段私有且为枚举 | 状态用字符串或开放写入 |
| AR-07 | 值对象字段 final | 值对象被改成可变 |
| AR-08 | 事件只由 domain 发布 | 应用层绕过聚合根直接发事件 |
| AR-09 | 跨模块不暴露领域实体 | 有人跨模块传实体而不是 DTO |
| AR-10 | 仓型比较只在 strategy 包 | 仓型判断散落进业务代码 |

十条全部是构建期失败，不存在"报告给人看"的环节。

## 约束与验证

| 约束 | 强制手段 |
|---|---|
| 新增架构约束必须先写断言 | 提交前检查：03 新增一条约束，必须同时在本文件加 AR 编号，否则视为未落地 |
| 断言与业务测试同批执行 | 构建配置：ArchUnit 测试放在 `src/test`，与单元测试一起跑，挂在 `mvn verify` |
| 断言失败即阻断合并 | CI：测试失败不产出镜像，不允许手动跳过 |
| 断言豁免必须登记 | 本文件新增一张"豁免清单"，写明类名、原因、到期时间；无到期的豁免不接受 |
| 规则实现随版本调整 | ArchUnit 的 API 在 1.x 内有变化，落地时以实际版本为准；规则意图不变 |

引用的决策编号：D09、D10、D49、D51；模块与分层规则见 03。

规则内容若需修改，先改 03 或 00，再改本文件的断言——不允许只改断言不改设计。

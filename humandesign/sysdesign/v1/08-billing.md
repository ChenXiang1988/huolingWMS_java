# 计费域

计费域是独立启动单元与独立库，只消费 WMS 推送的作业事实；算费到明细与账单、对账到与货主及财务系统对齐为止，开票与总账归外部财务系统。

---

## 问题

**解决**：定住计费域的边界与输入、合同与费率的结构、算费与冲正、账单与对账、财务系统对接、事实的幂等与迟到处理、计费域的权限。

**不解决**：WMS 侧事实如何产生（见 03、16）、库存模型（见 04）、费率的具体数值与商务条款（属合同内容）、财务报表与开票（属外部系统）。

---

## 设计

### 计费域只认事实，不认单据状态

输入是**作业事实**，不是单据。单据状态变化不产生费用，实际发生的作业才产生。

| 事实类型 | 触发时点 | 计费用途 |
|---|---|---|
| 收货 | 收货完成 | 入库操作费 |
| 上架 | 上架完成 | 上架操作费 |
| 存储 | 按日切扫描在库量 | 仓储费（按托/按件/按面积） |
| 拣货 | 拣货完成 | 出库操作费 |
| 复核 | 复核完成 | 复核费 |
| 发运 | 装车完成 | 装车费、月台占用费 |
| 加工 | 加工单完成 | 加工费（贴标、换包装、组合拆包） |
| 资源占用 | 按月台/人工时段 | 资源费 |

每条事实必须自带六个字段，缺一不可：

| 字段 | 作用 |
|---|---|
| 事实号 | 幂等键，全局唯一 |
| 货主 | 决定匹配哪份合同 |
| 仓库 | 决定费率卡的适用维度 |
| 发生时间 | 决定匹配哪个合同版本（见 D34） |
| 服务项 | 决定用哪条规则 |
| 数量与单位 | 计算基数 |

**事实不含金额**。金额由计费域算，不由 WMS 传——否则同一笔费用会有两个计算口径。

### 合同挂在货主上，一份覆盖全仓网

依据 D32、D33、D34。

| 对象 | 结构 | 关键约束 |
|---|---|---|
| 合同 | 货主 + 版本 + 生效期 + 账期 + 日切点 | 一个货主同时只有一份生效版本 |
| 合同版本 | 不可变，改价建新版本 | 按**事实发生日**匹配，不按当前版本回算 |
| 费率卡 | 按维度匹配：仓型 / 仓库 / 库区 / 服务项 | 同一维度只能命中一条，命中多条即配置错误 |
| 规则 | 取整、阶梯、最低消费、免租期 | 取整规则写进合同配置，不硬编（见 D35） |

无生效合同时，WMS 侧的受理校验会拦截（D33），计费域不负责拦作业，只负责算钱。

### 算费分三步，每步都可重放

```
作业事实 ──① 归集──> 事实表 ──② 算费──> 计费明细 ──③ 出账──> 账单
```

| 步骤 | 幂等键 | 重算后果 |
|---|---|---|
| ① 归集 | 事实号 | 重复投递直接丢弃，不产生第二条事实 |
| ② 算费 | 事实号 + 合同版本 | 同输入必得同输出，重算不改历史结果 |
| ③ 出账 | 账期 + 货主 | 未结账的账单可重出；已结账的只能下期调整 |

三步之间用"批次"隔离：一次算费覆盖一个时间窗，批次可重跑、可对比。

### 明细写入后不可改，只能冲正

依据 D36。

| 操作 | 允许 | 说明 |
|---|---|---|
| 新增明细 | 是 | 正常算费产出 |
| 修改明细金额 | **否** | 数据库层面禁止 UPDATE |
| 删除明细 | **否** | 数据库层面禁止 DELETE |
| 冲正 | 是 | 生成反向明细（金额取负）+ 新增明细，成对写入，互相引用 |
| 重算 | 是 | 生成新明细并冲销旧的，不覆盖 |

每条明细固定携带四个回溯字段，缺一不可（依据 D37）：

```
事实号 + 合同版本 + 规则快照 + 计算参数
```

**规则快照必须是快照，不能是规则 ID**。规则会改，只存 ID 的话，历史明细在规则变更后就解释不了自己。

### 日切按仓所在法域，时间统一存 UTC

依据 D38。

| 项 | 定法 |
|---|---|
| 存储 | 所有时间戳存 UTC |
| 日切点 | 按仓库所在法域时区，写进合同 |
| 日切计算 | 存储费按日切点的在库量算，不按自然日 0 点 |

同一货主跨法域有多仓时，各仓按各自的日切点算，出账时再合并——否则跨时区仓库的仓储费会多算或少算一天。

### 账单、对账、差异三者分开

| 对象 | 内容 | 可变性 |
|---|---|---|
| 账单 | 一个货主一个账期的汇总，含账单行 | 未结账可重出，结账后不可变 |
| 对账批次 | 一次对账的范围与结果 | 不可变，只追加 |
| 对账差异 | 三方比对出的不一致 | 可关闭、可转调整单，不改账单 |

对账三方：

| 方 | 比什么 |
|---|---|
| 货主 | 货主自查的库存与作业量 vs 我方事实 |
| WMS 事实 | 事实表与明细的对应关系是否完整 |
| 财务系统 | 已推送的应收 vs 财务侧已入账 |

差异处理只有两条路：**关闭（说明理由）** 或 **生成调整单（冲正）**。不允许直接改账单数字。

### 财务系统只做推送与回执，不做双写

依据 D50。

```
计费域 ──推账单或应收凭证──> 财务系统（金蝶等） ──回执──> 计费域
```

| 规则 | 内容 |
|---|---|
| 单向权威 | 应收金额以计费域为准，财务系统只记账不重算 |
| 失败重试 | 推送失败进重试队列，超次数转人工 |
| 不双写 | 不在两处同时维护同一笔应收 |
| 不开票 | 发票由财务系统开，WMS 不产生票号 |

推送记录必须留：推送时间、报文、回执状态、财务侧单号。对账时用财务侧单号回溯。

### 事实可以乱序到达，算费按发生时间排

MQ 不保证顺序，同一批事实可能乱序。

| 情形 | 处理 |
|---|---|
| 迟到但未出账 | 正常算入本账期 |
| 迟到且已出账 | 不进已结账账单，走下期调整单 |
| 重复投递 | 按事实号丢弃 |
| 事实被撤销（如单据取消后作业回滚） | 生成反向事实，不删除原事实 |

**事实不可删除**，只能反向冲销——与明细同源，这是审计要求。

### 作业要求项与计费事实同源

依据 D57 第 4 条：一处配置决定三件事——是否生成加工单、作业端是否出现任务、是否产生计费事实。

计费域不重复判断"这个货要不要贴标"，它只看有没有收到加工完成事实。要求项配在 WMS 侧，计费侧只消费结果。这样避免两处配置漂移。

### 计费域的表分五组

| 组 | 表 |
|---|---|
| 主数据 | 合同、合同版本、费率卡、规则、取整配置 |
| 事实 | 作业事实、事实明细、反向事实 |
| 计算 | 计费明细、算费批次、账单、账单行 |
| 对账 | 对账批次、对账差异、差异处理记录 |
| 集成 | 财务推送记录、回执、重试队列 |

五组共库不同 schema，与 WMS 库存库完全隔离（D49）。

### 权限独立于作业岗

依据 D39，接 19 的权限点体系。

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| 计费专员 | 维护合同、费率卡、规则；发起算费 | 不能出账、不能确认收款 |
| 对账员 | 核对事实与明细、出账、处理差异 | 不能改合同与费率 |
| 作业岗 | — | 不得出现任何改价入口 |

两个角色不得由同一账号兼任。

## 约束与验证

| 约束 | 强制手段 |
|---|---|
| 事实不含金额 | 接口层：事实 DTO 无金额字段；代码层：ArchUnit 断言计费域不引用 WMS 的金额类 |
| 明细不可改 | 数据库层：明细表仅授予 INSERT 权限，无 UPDATE / DELETE |
| 明细可回溯 | 数据库层：四个回溯字段非空约束；核对层：抽样重算对比 |
| 合同按事实发生日匹配 | 应用层：算费前按 `发生时间` 查版本，不取最新版本 |
| 日切按仓法域 | 应用层：日切时间由仓配置决定；测试：跨时区用例必须覆盖 |
| 不双写财务系统 | 集成层：只保留推送与回执两张表，无财务侧业务表副本 |
| 事实不可删 | 数据库层：事实表无 DELETE 权限；反向事实必须引用原事实号 |
| 计费域不依赖 WMS 库 | 部署层：独立库与独立账号（D49）；代码层：只依赖事件契约 DTO |
| 权限与作业分离 | 应用层：计费权限点不出现在作业端菜单；19 的权限点上架时校验 |

引用的决策编号：D32 至 D39、D49、D50、D57；不变量：INV-13、INV-14、INV-15；单据侧事实来源见 16，权限点体系见 19。

WMS 侧不判断金额、不存价目表、不做账单。任何"在作业端显示费用"的需求，都是查询计费域的只读接口，不是把费用写进 WMS。

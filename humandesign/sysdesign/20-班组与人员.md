# 班组与人员

班组是仓内现场作业组织，不是权限组织；一人同一时刻只有一个主属班组，班组长是归属记录上的职务而不是系统角色；现场作业员工由单仓端建档与办理离职，人员状态只有登录与未登录，不做考勤与排班。

---

## 问题

**解决**：定住班组的树形组织与状态、人员入组与调组、班组职务与系统角色的权限分工、登录状态与可派工名单、名单查询与筛选、表结构与关键约束、异常处理。

**不解决**：角色权限点与全局治理角色（见 05、19；单仓端只授现场作业员与单仓管理者角色）、请假、缺勤、在岗与离岗、排班、工时、薪资（按 D61 一律不做）、派工算法（见 06，本文只提供候选数据）、交接班单据（见 00 D53、16）、移动作业端页面骨架（见 12b）。

**与相邻文档的关系**：05 定四个端的系统角色，本文定班组职务；03 的 M11 是本文的代码归属；15 定上下文与词表；19 定鉴权链路；12a 定页面骨架。本文不重新定义这些内容。

---

## 设计

### 班组树最多三层，只表达作业分工

班组只服务三件事：派工范围、按组看进度、按组追责任。三层以上没有对应的作业动作，继续加深就变成人事组织架构，与 D60 冲突。

```
仓 warehouse
└── 班组 team（1~3 层）
    ├── 班组长 0..1（team_member.member_role = LEADER）
    ├── 副组长 0..1（DEPUTY）
    └── 成员 0..N（MEMBER）

员工 employee（Site 权威，全部员工一份档案；与账号一对一）
├── 1:0..1 当前主属归属 team_member（left_at 为空）
├── 1:0..N 历史归属
└── 1:0..1 当前临时支援 team_support
```

班组类型只用于筛选与看板，不参与权限判断：

| 类型 | 典型职责 | 不决定什么 |
|---|---|---|
| 收货 | 卸货、清点、收货扫码 | 不决定谁能收货，权限仍看角色 |
| 上架 | 搬运、上架、库位确认 | 不决定库位选择，选址看策略 |
| 拣货 | 按任务拣货、集货 | 不决定波次怎么合 |
| 复核 | 出库复核、异常拦截 | 不决定谁必须复核，人员约束看 D53 |
| 打包 | 装箱、封箱、贴标 | 不决定包装规格 |
| 盘点 | 分区循环盘点 | 不决定盘点计划 |
| 机动 | 跨组支援、临时补位 | 不改变成员主属 |
| 其他 | 未归入以上类型的组 | — |

#### 班组状态只有三种，删除等于归档

| 从 | 到 | 触发者 | 前置条件 | 不满足时 |
|---|---|---|---|---|
| （无） | 启用 | 单仓管理者 | 编码仓内唯一、父节点启用、深度合法 | 拒绝创建，表单内逐条提示 |
| 启用 | 停用 | 单仓管理者 | 无 | — |
| 停用 | 启用 | 单仓管理者 | 父节点启用 | 拒绝，提示先启用父节点 |
| 停用 | 归档 | 单仓管理者 | 无当前成员、无未归档子班组 | 拒绝，列出成员数与子班组 |
| 归档 | — | — | 不可恢复写入 | 只能查看历史 |

停用不禁用现有成员：整组暂停时人还挂在组里，强制调出会制造假数据。归档才要求清空，且只做逻辑删除（INV-18）。

#### 班组规则

| 编号 | 规则 | 强制手段 |
|---|---|---|
| TR-01 | 班组必须属于当前仓，父子必须同仓 | 应用校验：`warehouse_id` 取自会话；创建与移动时校验父子同仓 |
| TR-02 | 班组编码仓内唯一，创建后不可改；可自动生成，格式为 `T` 加四位序号，允许手填 | 数据库：`UNIQUE (warehouse_id, team_code)`；应用：更新接口不接受编码 |
| TR-03 | 同一父节点下名称唯一，忽略大小写与首尾空格 | 数据库：表达式唯一索引 |
| TR-04 | 深度不超过三层，仓根不计 | 数据库：`CHECK (depth BETWEEN 1 AND 3)`；应用：移动时校验子树最大深度 |
| TR-05 | 不能成环，目标父不得在自身子树内 | 应用校验：`path` 前缀判断 + 事务内锁 |
| TR-06 | 移动只改子树的 `path` 与 `depth`，不改成员归属与历史 | 应用：同一事务更新子树；历史表不写 |
| TR-07 | 停用只禁止新增与调入，现有成员保留 | 应用：入组与调组校验目标状态 |
| TR-08 | 归档要求无当前成员、无未归档子班组、无进行中支援与代班 | 应用：归档前逐项校验并列出未满足项 |
| TR-09 | 班组类型与排序不参与鉴权与派工优先级 | 代码检查：权限与派工代码不读这两个字段 |
| TR-10 | 班组不设人数上限 | 数据库：无人数字段；应用：入组不校验上限 |
| TR-11 | 班组不物理删除 | 数据库：应用账号无 `DELETE` 权限；表设计：状态字段 |
| TR-12 | 班组变更留痕：创建、改名、移动、停用、归档、启用 | 应用：写 `team_change_log`，记录变更前后值与操作人 |

### 员工档案归单仓端，管理岗是角色

招聘在当地发生，建档、改档、离职也在当地。本仓全部员工一份档案，归单仓端；管理岗不是另一类档案，而是持单仓管理者角色的员工。

| 项 | 规定 |
|---|---|
| 档案 | 本仓全部员工一份档案，归 Site；不按作业岗与管理岗拆两份 |
| 管理岗 | 持单仓管理者角色；角色收回即不再是管理岗 |
| 建档入口 | 单仓端「班组与人员 → 新增员工」；运营端不建仓内员工档案 |
| 员工号 | 仓编码加四位序号，单仓端生成，全局唯一 |
| 账号 | 单仓端可开作业账号、授本仓管理角色；不能授全局治理角色 |
| 改档 | 单仓端可改姓名、手机号、资格备注；员工号、所属仓不可改 |
| 离职 | 单仓端办理：置离职、停账号、结束归属、失效会话 |
| 跨仓 | 首期不做调仓；原仓离职、新仓入职 |
| 运营端 | 只读员工副本；授全局治理角色；不建档案 |

| 编号 | 规则 | 强制手段 |
|---|---|---|
| SF-01 | 员工档案只有一份，全部归单仓端 | 应用：运营端没有建档接口；不设岗位类别字段 |
| SF-02 | 管理岗由单仓管理者角色派生，不写档案字段 | 应用：名单显示角色，不显示岗位类别；角色收回即失去管理岗标记 |
| SF-03 | 单仓端可授现场作业员与单仓管理者角色，限本仓 | 应用：角色白名单；数据域固定本仓 |
| SF-04 | 单仓端不能授计费、对账、跨仓调度、权限管理员 | 应用：白名单外返回 403 |
| SF-05 | 不能自授；至少保留一个可用单仓管理者 | 应用：操作者与目标账号相同拒绝；免职前校验管理者数量 |
| SF-06 | 员工号自动生成，格式为仓编码加四位序号 | 应用：生成后由唯一索引兜底；不开放手填与修改 |
| SF-07 | 所属仓不可改；跨仓走原仓离职加新仓入职 | 应用：更新接口不接受所属仓 |
| SF-08 | 离职必须置离职、结束归属、失效会话，并同步请求停账号 | 应用：本地事务完成前三项；停账号失败进重试队列；有任务先改派 |
| SF-09 | 离职不删档案，历史归属保留 | 数据库：应用账号无删除权限；任职状态字段 |
| SF-10 | 有账号时与员工一对一；账号停用不等于离职 | 应用：`account.employee_id` 唯一；账号状态与任职状态分开提示 |

账号仍由 Hub 统一持有与鉴权，单仓端只是开通与授权入口：

| 项 | 规定 |
|---|---|
| 默认角色 | 现场作业员，端为单仓端与作业端 |
| 可加角色 | 单仓管理者，端为单仓端；限本仓 |
| 数据域 | 固定本仓，不写 `role_scope`；由会话固定域收口 |
| 不能授予 | 计费专员、对账员、跨仓调度员、权限管理员 |
| 自授限制 | 不能给自己开账号、授角色、停账号 |
| 管理者数量 | 至少保留一个可用单仓管理者；免职或停用最后一个都拒绝 |
| 停用 | 单仓端可停用本仓现场作业员与单仓管理者账号；权限管理员账号归运营端 |

### 人员与班组是多对一的历史关系

不把 `team_id` 放在员工表上。调动若覆盖字段，历史就没了；并发调动还会产生双归属。用独立的归属记录，当前归属就是 `left_at IS NULL` 的那一条。

| 编号 | 规则 | 强制手段 |
|---|---|---|
| MR-01 | 一人同一时刻只有一条有效主属归属 | 数据库：部分唯一索引 `UNIQUE (employee_id) WHERE left_at IS NULL` |
| MR-02 | 一个班组同一时刻最多一名班组长、一名副组长 | 数据库：两条部分唯一索引，条件分别为 `member_role = 'LEADER'` 与 `'DEPUTY'`，且 `left_at IS NULL` |
| MR-03 | 班组长与副组长必须是本组当前成员 | 应用：同一事务先校验归属，再写职务 |
| MR-04 | 一人同一时刻最多担任一个班组的班组长 | 数据库：部分唯一索引 `UNIQUE (employee_id) WHERE member_role = 'LEADER' AND left_at IS NULL` |
| MR-05 | 调动 = 结束原归属 + 新建目标归属，同一事务 | 应用：事务内 `SELECT ... FOR UPDATE` 锁员工当前归属 |
| MR-06 | 班组长调出前必须先任免新组长或设代班 | 应用：调出前校验，不满足拒绝并给「先去任免」入口 |
| MR-07 | 临时支援不改主属，只在支援期可被目标组派工；目标组停用或归档时支援立即结束 | 应用：支援记录；派工候选合并主属与有效支援；状态变更触发结束 |
| MR-08 | 同一人同一时间只有一条有效支援、一条有效代班 | 数据库：两条排除约束，时间区间不重叠 |
| MR-09 | 离职由单仓端办理；离职不可恢复，重新入职新建档案 | 应用：离职接口在 Site；离职后入组拒绝；最后一个管理者离职前要求先补授或由运营端补授 |
| MR-10 | 停用人员 = 结束归属，不删档案、不停账号；无有效归属即不可派工 | 应用：两个动作分开；页面提示账号可单独停用，停用后不能登录 |

#### 调动只有三种，主属是否改变是关键区别

| 类型 | 适用 | 主属 | 目标组可派工 | 结束方式 |
|---|---|---|---|---|
| 长期调动 | 换班组、组织调整 | 改到目标组 | 是 | 无到期，直到下次调动 |
| 临时支援 | 借人、跨组补位 | 不变 | 是，仅支援期内 | 到期自动结束，可提前结束 |
| 离场 | 离开本仓 | 结束 | 否 | 手动停用或单仓端办理离职 |

长期调动一次一人或批量，批量要求目标班组相同；逐人事务，部分成功可接受，返回成功与失败清单。一个人失败不应阻塞同批其他人。首期只支持即时生效；表里的 `effective_at` 保留为扩展，不做预约调动。

#### 班组长与副组长

- 班组长从本组当前成员中选，任免即写归属记录的 `member_role`，不新建账号角色。
- 任免新组长时，原组长自动降为成员，操作人可选择同时设为副组长；设原组长为副组长时，原副组长降为成员，一组始终只有一名副组长。
- 班组长可空缺。空缺时副组长自动代行班组事务权，但不含任免与设代班；没有副组长则由单仓管理者代管，看板标「组长空缺」。
- 一个班组同一时间只有一个代班。代理期间原组长职务保留，事务权优先给代班人；原组长可提前收回。
- 组长离职或调出导致强制结束时，系统只置「组长空缺」并告警，不自动指定接班人；账号停用只告警，不自动免职。

### 班组长是班组职务，不是系统角色

把班组长做成系统角色会带来四个问题：

| 问题 | 说明 |
|---|---|
| 回收不及时 | 角色挂账号，调组后要额外回收；漏一次就留下跨组权限 |
| 破坏两维数据域 | 05 与 19 的数据域只有货主与仓；加班组维度要改鉴权模型，而班组范围是对象级而非通用域 |
| 角色叠加混乱 | 一个人可以同时是现场作业员与某组班组长，两者是叠加关系，不是并列枚举 |
| 每次请求要解析班组 | 角色鉴权发生在四道门，班组归属要查业务表；放进权限模型会把业务查询塞进鉴权链路 |

所以本文把权限分两层：系统角色决定「能不能进这个页面、能不能用这个功能」，班组职务与归属决定「能对哪个班组、哪些人做」。

| 维度 | 系统角色（见 05） | 班组职务（本文） |
|---|---|---|
| 载体 | 账号与角色关联 | 班组归属记录的职务字段 |
| 生效范围 | 端 + 货主与仓两个数据域 | 单个班组 |
| 变更方式 | 权限管理员授权 | 单仓管理者任免，随调组失效 |
| 鉴权位置 | 19 的四道门 | 应用层对象校验 |
| 是否进权限点 | 是 | 否 |

| 新建、编辑、停用、归档班组 | 写 | — | — | — | — | — |

三条越权校验：

1. 服务端从会话取当前员工，再查其有效归属，不信任请求里的班组标识。
2. 请求携带的班组标识与会话归属比对，不一致直接 403；查看子组按 `path` 前缀放行。
3. 班组长只能看本组与子组，不能改子组人员；要改需子组组长或单仓管理者操作。

### 登录状态只有已登录与未登录

人员状态按 D61 只有已登录与未登录两种。它由会话派生，不单独维护业务表，也不延伸出在岗、离岗、请假、缺勤。查询失败时显示的「未知」是查询结果，不是第三种人员状态。

| 状态 | 含义 | 可派工 | 变为该状态 | 离开该状态 |
|---|---|---|---|---|
| 已登录 | 当前存在有效会话 | 是，仍需其他条件满足 | 登录成功 | 主动退登、会话超时、账号停用、离职 |
| 未登录 | 当前没有有效会话 | 否 | 退登、超时、停用、离职、从未登录 | 重新登录 |

同一员工在单仓端与移动作业端各有一个会话时，任一会话有效即为已登录。会话按端与仓固定，不跨仓合并。换班按 D24 必须退登；未退登的会话在超时前仍算已登录，系统不因为人离开工位就改状态。

#### 登录状态规则

| 编号 | 规则 | 强制手段 |
|---|---|---|
| OR-01 | 登录状态由会话服务派生，不落业务表 | 代码检查：业务库无人员状态表；查询走会话服务 |
| OR-02 | 登录成功即已登录；退登、超时、停用、离职即未登录 | 应用：登录与退登写会话；停用与离职主动失效会话 |
| OR-03 | 不做登录时长、登录历史与考勤统计 | 代码检查：无登录时长字段与考勤报表；登录事件只进安全审计 |
| OR-04 | 已登录不等于在工位，系统不据此判断现场位置 | 设计评审：任何「已登录即视为在工位」的规则驳回 |
| OR-05 | 会话服务不可用时登录状态显示未知，不按未登录处理 | 应用：返回未知；派工候选拒绝生成并提示稍后重试 |
| OR-06 | 可派工实时组合，不存布尔字段 | 应用：查询服务实时计算；表结构无 `can_dispatch` |

#### 可派工由五项人员条件加任务条件实时判定

```
可派工 = 在职
      且 账号启用
      且 有有效主属归属且班组启用
      且 已登录
      且 可作业资格不是禁止
      且 无进行中任务
```

前五项是人员条件，分别由员工档案与资格、账号、班组归属、会话维护；最后一项来自任务模块的只读查询（06 一人同一时刻一个进行中任务组）。这些条件都不落成一个字段：五个来源不同步时，存字段必然给出错误答案。

可作业资格是能力标记，不是人员状态：

| 编号 | 规则 | 强制手段 |
|---|---|---|
| ER-01 | 资格只有正常、限制、禁止三值，由单仓管理者维护 | 数据库枚举检查；应用写 `team_change_log`，`employee_id` 非空、`team_id` 为空 |
| ER-02 | 资格为禁止的人不进派工候选，登录状态照常显示 | 应用：候选查询过滤；名单不隐藏该人 |
| ER-03 | 资格不参与计费、绩效与工资 | 代码检查：计费模块不读资格字段 |

### 派工只读可用性，不反向改班组

- 06 首期由单仓管理者派单，本文不改变派工入口与三档策略。
- 任务模块通过只读查询服务取候选：班组启用、已登录、资格不是禁止、无进行中任务。它不写班组表，也不维护登录状态。
- 班组管理不写任务；任务改派不改人员归属。D52 提到的「班组派工」若启用，另改 06 与作业策略，不在本文预设。
- 交接班按 D53 走单据，单据可引用班组与班组长快照；本文只提供数据，不写交接单。
- 看板按班组汇总已登录人数、可派工与进行中任务数，最终一致，允许延迟。
- 登录状态、资格与班组归属都不参与计费。

## 约束与验证

| 约束 | 强制手段 | 落点 |
|---|---|---|
| 一人一条有效主属归属 | 数据库部分唯一索引 | `team_member` |
| 一组一名班组长、一名副组长 | 数据库部分唯一索引 | `team_member` |
| 班组长必须是本组成员 | 应用校验，同事务校验归属 | 任免接口 |
| 一人最多担任一个组班组长 | 数据库部分唯一索引 | `team_member` |
| 班组树不成环、不超三层、不跨仓 | 应用校验 + `CHECK` + 事务锁 | 创建与移动接口 |
| 同一父下班组不重名 | 数据库表达式唯一索引 | `team` |
| 班组编码仓内唯一且不可改 | 数据库唯一索引 + 接口不接受编码 | `team` |
| 归档前必须清空成员、子组与未结束的支援和代班 | 应用逐项校验并列出未满足项 | 归档接口 |
| 班组与归属不物理删除 | 应用账号无删除权限 | `team`、`team_member` |
| 停用人员不删档案、不停账号 | 应用只结束归属；无有效归属即不可派工 | 停用接口 |
| 调动原子完成 | 事务 + 员工当前归属行锁 | 调动接口 |
| 支援与代班时间不重叠 | 数据库排除约束 | `team_support`、`team_leader_proxy` |
| 登录状态不落业务表 | 代码检查：业务库无状态表；查询走会话服务 | 表结构与名单查询 |
| 会话服务不可用不得按未登录处理 | 应用：返回未知；派工候选拒绝生成 | 名单与候选接口 |
| 不做登录时长与考勤 | 代码检查：无时长字段、无考勤报表 | 全模块 |
| 可派工不存字段 | 代码检查：人员表无 `can_dispatch` 字段 | 表结构与查询 |
| 停用班组不产生派工候选 | 应用：候选查询校验班组状态为启用 | 派工候选查询 |
| 班组长不能操作子组人员 | 应用对象校验，按 `path` 前缀只放行查看 | 人员与资格接口 |
| 数据域固定本仓 | 仓储层注入 `warehouse_id`；参数不得覆盖 | 全部查询与写入 |
| Site 员工表只由 M11 写 | 构建层：Site 数据源账号只授 M11；员工档案只有一份 | `employee` |
| 角色权限只由 M01 写 | 构建层：单仓端只调权限接口，不写角色权限表 | `role`、`account_role` |
| 单仓端只能授现场作业员与单仓管理者角色 | 应用：角色白名单加本仓固定域；白名单外 403 | 账号与角色接口 |
| 至少保留一个单仓管理者 | 应用：免职或停用前校验；为零时拒绝，由运营端补授 | 角色与账号接口 |
| 不能自授 | 应用：操作者与目标账号相同拒绝 | 账号与角色接口 |
| 员工号全局唯一且不可改 | 数据库唯一索引 + 更新接口不接受员工号 | `employee` |
| 员工与账号一对一 | 数据库唯一索引 `account.employee_id`；货主账号为空 | `account` |
| 管理岗由角色派生，不设岗位字段 | 代码检查：`employee` 无 `job_type`；名单角色来自账号 | `employee` |
| 所属仓不可改 | 应用：更新接口不接受所属仓 | `employee` |
| 离职必须停账号 | 应用：离职用例发停用请求；失败进重试队列；核对任务扫描未停账号 | 离职接口 |
| 账号服务不可用不阻断档案与归属 | 应用：档案与归属本地事务；账号请求进重试队列 | 档案与离职接口 |
| 统计与列表同源 | 同一查询服务 | 名单页 |

## 异常处理

| 场景 | 系统行为 | 提示要点 | 留痕 |
|---|---|---|---|
| 班组编码重复 | 拒绝创建 | 编码已被占用，换一个 | 无 |
| 同父下班组重名 | 拒绝 | 同级已有同名班组 | 无 |
| 层级超过三层 | 拒绝创建或移动 | 班组最多三层，请挂到更上层 | 无 |
| 目标父在自身子树内 | 拒绝移动 | 不能把班组移到自己的子组下 | 无 |
| 父子跨仓 | 拒绝 | 班组只能在本仓内组织 | 无 |
| 停用班组加人 | 拒绝，入口置灰 | 班组已停用，先启用 | 无 |
| 删除仍有成员的班组 | 拒绝，列出成员 | 先调出 N 人 | 无 |
| 删除仍有子班组的班组 | 拒绝，列出子组 | 先归档子班组 | 无 |
| 删除仍有支援或代班的班组 | 拒绝，列出关系 | 先结束支援与代班 | 无 |
| 人员已在其他班组 | 拒绝入组，显示所在组 | 先办理调动 | 无 |
| 人员已离职 | 拒绝入组 | 离职不可恢复；重新入职新建档案 | 无 |
| 人员不属于本仓 | 拒绝入组 | 首期不做跨仓调仓；原仓离职、新仓入职 | 无 |
| 跨仓直接改所属仓 | 拒绝 | 首期不做调仓；原仓离职、新仓入职 | 无 |
| 班组长调出未交接 | 拒绝调动 | 先任免新组长或设代班 | 无 |
| 任免非本组成员 | 拒绝 | 只能从本组当前成员中选 | 无 |
| 一人被任两个组组长 | 拒绝 | 同一时间只能担任一个组的班组长 | 无 |
| 代班或支援时间重叠 | 拒绝 | 显示已有区间，要求先结束 | 无 |
| 并发修改同一人归属 | 后提交者冲突 | 数据已变化，请刷新后重试 | 无 |
| 员工号生成冲突 | 自动重试下一个序号；连续失败拒绝 | 重新提交 | 无 |
| 账号开通失败 | 员工已建档，账号标记待开通 | 账号待开通，可重试；未开通前不能被派工 | 无 |
| 账号服务不可用 | 员工档案与班组归属照常保存；账号待开通或待停用 | 账号操作稍后重试，现场作业不受影响 | 无 |
| 单仓端授计费、对账、跨仓调度、权限管理员角色 | 返回 403 | 只能授现场作业员与单仓管理者 | 操作日志 |
| 单仓端给自己授角色 | 返回 403 | 不能自授，请由其他管理者操作 | 操作日志 |
| 免职或停用最后一个单仓管理者 | 拒绝 | 至少保留一个可用管理者；需要运营端补授 | 操作日志 |
| 离职时账号停用失败 | 本地离职与归属结束照常完成，账号停用进重试队列 | 账号将在恢复后停用 | 操作日志 |
| 班组长访问其他班组 | 返回 403 | 无权查看该班组 | 操作日志 |
| 批量调动部分失败 | 成功的生效，返回失败清单 | 列出失败人与原因 | 调动流水 |
| 导出超过 5000 行 | 拒绝导出 | 缩小筛选范围后重试 | 操作日志 |
| 会话超时 | 名单显示未登录；已指派任务保留 | 重新登录后继续处理任务 | 无 |
| 账号停用但会话未过期 | 下次请求鉴权失败并失效会话，名单显示未登录 | 账号已停用，请联系权限管理员 | 操作日志 |
| 停用人员有进行中任务 | 允许停用，任务保持已指派 | 该员工有进行中任务，停用后仍可完成 | 无 |
| 离职时仍有进行中任务 | 拒绝离职，列出进行中任务 | 先将任务改派给他人 | 无 |
| 登录状态查询失败 | 显示未知，派工候选拒绝生成 | 登录状态暂时不可用，稍后重试 | 无 |

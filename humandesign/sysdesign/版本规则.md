# 设计文档版本演进规则

## 结论

**当前有效版本由同目录 [`current-version.txt`](current-version.txt) 指定，本文件不登记当前版本号。** 所有设计修改只在指针指向的版本目录内进行，其余版本目录已冻结为历史快照。

判断版本的机器可读依据就是这个指针文件：代理、子代理与校验脚本都读它，而不是靠人打开某个索引去发现状态。代理侧的完整禁令见 `.codebuddy/rules/version-policy.md`，脚本侧的版本门禁见 `check-design.py` 的 `VER-01`。版本号只允许出现在指针文件与本文末尾的版本记录表两处。

本文件常驻 `sysdesign/` 根目录，不随任何版本归档，是「以后再重构时沿用同一套方法」的唯一依据。判断该改哪份文档，第一步永远是读指针文件。

## 一、为什么按版本目录管理

同一套规则若在归档版与当前版各留一份，修订时就必然出现「改了旧的、没改新的」，v1 的 48 条缺陷中有 19 条权威源冲突正由此产生。版本目录把「历史论证」与「当前结论」物理隔开：旧版只读、新版唯一可改，权威源自然唯一。

## 二、目录与文件约定

| 约定 | 内容 |
|---|---|
| 版本目录名 | `v1`、`v2`、`v3`…… 序号只增不改；**目录名不带状态词**，状态由目录内 `index.md` 声明 |
| 机器可读指针 | 根目录 `current-version.txt`，一行一个版本目录名，是代理与脚本判断当前版本的唯一事实来源 |
| 状态为什么不放目录名 | 目录改名会让所有跨文档链接与历史引用失效；改 `index.md` 一行即可完成状态切换 |
| 每个版本目录必须有一个 `index.md` | 见第三节的固定内容 |
| 每个版本目录有自己的 `log.md` | 归档版的日志停止追加；当前版的日志持续追加 |
| 根目录常驻文件 | 本文件；以及 `review/`，作为跨版本的审查档案，不随版本归档 |
| 目录名稳定 | 一旦某版被标为已过期，其目录路径永久不变，允许被引用为历史 |

## 三、每个 `index.md` 必须包含的六项内容

1. **状态声明**：第一行给出「生效中」或「已过期」，并指向接替版本或前一版本。
2. **本版结论**：一句话说明本版相对上一版改了什么、为什么改。
3. **文档清单**：逐份列文件名、职责、状态；未落盘的也要登记状态，不写空壳文件充数。
4. **变更依据**：指向 `review/` 中的审查材料或本版的变更提案。
5. **只读或可改规则**：明确本目录是否接受修改，以及修改落在哪个目录。
6. **版本规则引用**：指向根目录本文件。

除此之外，当前版本的 `index.md` 还须给出文档分组、阅读路线、文档约定与待定项去向；归档版本的 `index.md` 还须给出归档日期、归档动作与已知失效项。

## 四、版本升级六步（以后每次重构照此执行）

按此顺序串行，不并行、不跳步。

| 步 | 动作 | 完成判据 |
|---|---|---|
| 1 | 先在**当前版本**的 `index.md` 顶部把状态改为「已过期」，写清接替版本号、过期日期与归档原因 | 旧版索引第一行可读出「不可再改」 |
| 2 | 新建下一序号目录 `vN+1/`，目录名只含序号 | 目录存在且为空 |
| 3 | 在新目录写 `index.md`，状态标「生效中」，按第三节列全六项，并逐份登记文档的承继或重写状态 | 清单可逐行回查，无空壳文件 |
| 4 | 写新文档。能定稿的写定稿；未定稿的只在索引里登记状态与迁入批次，**不复制旧文档充当新文档**，避免把过期口径搬进新版 | 新版内每份文档都能通过金字塔四项与互斥穷尽自检 |
| 5 | 只更新两处：`current-version.txt` 与本文第七节的版本记录表。规则文件与子代理定义写 `<当前版>` 占位符，不写具体目录，故不随升级改动 | 指针与记录表一致；脚本与规则文件均无需改动 |
| 6 | 在新目录 `log.md` 记一行「vN+1 建立」；旧目录 `log.md` 停止追加 | 变更链闭合 |

回退方式：因目录名稳定、旧版内容未动，回退只需把本文件指针改回旧版、把两版 `index.md` 的状态行改回去，链接不会断。

## 五、引用与修改规则

1. 设计文档之间**只引用当前版本**内的文档与编号；需要溯源时引用 `vN/` 并显式标注「历史版本，仅供溯源」。
2. 编号（`Dxx`、`INV-xx`、`AR-xx`、`UI-*`、模块号、文档号）只增不改、不复用；跨版本沿用编号时须在新版登记「承继」关系。
3. 归档目录内禁止任何新增、修改、删除；发现归档版有误，处理方式是在当前版写一条「更正说明」并记入新版日志，不回改历史。
4. 待定项统一登记在当前版本的 `23-权威源与引用矩阵.md`，不在多份文档里各留一份。
5. 每份新文档采用当前版 `index.md` 规定的统一骨架；与决策冲突时先改决策文档，再逐层同步，并记录到新版日志。

## 六、升级检查清单

升级前：旧版审查材料是否齐备、待拍板的业务决策是否已列明、新版结构与章节层级是否已评审通过。

升级后：逐份检查结论先行、以上统下、归类分组、逻辑递进；逐类检查枚举相互独立且完全穷尽；检查编号唯一与引用可解析；检查每份「生效中」文档在新版日志中有对应记录；检查归档版第一行确为过期声明；检查版本号只存在于指针与本文记录表（`grep -rn "sysdesign/v[0-9]" .codebuddy CODEBUDDY.md --include="*.md"` 应无命中），并跑一次 `check-design.py --list-checks` 确认 `VER-01` 已注册。检查方法见 `review/R4-验证说明.md`。

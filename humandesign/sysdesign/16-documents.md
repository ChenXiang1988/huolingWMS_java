# 单据模型

所有单据共用一套单头与单行，按「单行是否必须带库位」分成履约单与作业单两族；状态统一五态，进度一律不进状态；新增类型只加类型枚举与一张扩展表。

---

## 问题

**解决**：定住单据的分族与结构、单头六组字段、五态与流转、受理校验、履约数量的汇总方式、差异关闭、扩展成本、单据与任务及计费的关系。

**不解决**：库存账户与锁定量（见 04）、任务拆分与波次（见 06、17）、算费规则（见 08）、表字段清单（见 11）。

---

## 设计

### 两族共用骨架，分族只看单行是否必须带库位

依据 D56。

| 族 | 面向 | 单行装什么 | 包含单据 |
|---|---|---|---|
| 履约单 | 货主与计费口径 | 货品要求：SKU、批次、要求数量、质量要求、包装要求、库区约束 | 入库通知单、收货单、出库单、调拨下行单 |
| 作业单 | 仓内操作指令 | 库位动作与库位对象 | 移库单、盘点单、加工单、冻结解冻单 |

分族的依据只有一条：**履约单的库位由策略决定，作业单离开库位无法表达**。两族共用单头与状态机，差异只在单行。

### 单头只装六组，多一列都不加

| 组 | 内容 |
|---|---|
| 身份 | 系统单号、类型、来源、外部单号 |
| 归属 | 货主、仓库，均非空 |
| 时间 | 提交、受理、业务要求时间、完成 |
| 状态 | 五态之一 |
| 关联 | 父单号、原单号 |
| 留痕 | 创建人、确认人、版本（乐观锁） |

类型专有字段（承运商、来源方式之类）不塞进单头，进 1:1 扩展表。单头一旦出现一堆可空列，查询与约束都会被拖垮。

### 单号在单仓端生成，不依赖运营端

| 编号 | 格式 | 用途 |
|---|---|---|
| 系统单号 | 类型前缀 + 仓编码 + 日期 + 当日序号 | 现场沟通与打印 |
| 外部单号 | 上游或客户提供 | 幂等键（见 D21） |

现场补录也要能出号，所以号段在单仓端生成，不走运营端协调。外部单号在货主范围内唯一，重复提交返回首次结果。

### 五态一套，所有类型相同

| 状态 | 进入条件 | 允许的操作 |
|---|---|---|
| 已受理 | 受理校验通过 | 生成任务、取消 |
| 执行中 | 第一个任务开始 | 记录履约、异常上报 |
| 已完成 | 全部任务完成且数量满足 | 无（只读） |
| 差异关闭 | 人确认短量并填原因 | 无（只读） |
| 已取消 | 人取消且锁定已释放 | 无 |

三条硬规则（依据 D56）：

1. **进度不是状态**。到货中、待上架、拣货中这类是任务反推出的辅助信息，用于列表展示，不入状态字段。
2. **不设「部分完成」终态**。要么完成，要么人工确认后差异关闭，不允许单据长期悬空。
3. **状态只由任务事件推进**，不接受前端直接改。人的操作只有三种：受理、确认差异关闭、取消。

### 受理必须过四道校验

| 校验 | 不通过的处理 | 依据 |
|---|---|---|
| 仓库处于生效状态 | 拒绝，提示仓未生效或缺库位 | D41 |
| 货主有生效合同 | 拒绝，提示无生效合同 | D33 |
| SKU 存在且属于该货主 | 拒绝，列出不匹配的行 | D02 |
| 作业单额外校验目标库位可用 | 拒绝，列出不可用库位 | 04 |

四道全是硬拦，不提供「强制受理」入口。受理通过后单据进入已受理，才允许生成任务。

### 履约数量是汇总值，不实时聚合

单行维护两个数值：已履约数量、差异数量。由任务完成事件回写。

| 做法 | 为什么 |
|---|---|
| 汇总值写在单行 | 单据列表要按履约进度排序与筛选，实时聚合任务表会把列表拖死 |
| 日结核对 | 汇总值必须等于任务片之和，对不上即告警 |
| 不做实时聚合 | 只在详情页单张单据上允许实时查，列表一律用汇总值 |

### 短量走差异关闭，不设部分完成

应收 100 实收 98 时：

1. 单据停在「执行中」，任务侧记录差异量；
2. 系统算出差异，生成待确认项；
3. 人填原因并确认，单据转「差异关闭」，三项留痕：差异量、原因、确认人。

不允许「数量不足就自动按实收完成」。差异必须有人签字，这是审计要求。

### 新增类型的成本固定：一个枚举加一张扩展表

| 步骤 | 内容 |
|---|---|
| 1 | 加一个单据类型枚举值 |
| 2 | 建一张 1:1 扩展表放类型专有字段 |
| 3 | 不动单头单行、不动状态机、不改已有查询 |

验收标准：加一种单据如果要改状态机或已有表结构，说明框架没定住。

### 四条边界

| 边界 | 内容 |
|---|---|
| 一单一货主一仓 | 不跨。调拨拆成源仓出库单与目的仓入库单，父单号关联 |
| 履约单行不指定具体库位 | 只到库区或库位类型 |
| 单据不存人、设备、波次 | 波次成员关系记在成员表；挂单头的话，一张单就进不了第二个波次 |
| 单据不改库存 | 只产生任务（见 03、06） |

### 作业要求项挂在单行上可覆盖，主流程不分叉

依据 D57。

```
单据行显式指定  >  货品作业要求  >  货主默认  >  仓库默认
```

| 规则 | 内容 |
|---|---|
| 就近覆盖 | 某一级有显式值就以该级为准，其余层不参与判断 |
| 单据行是本次例外 | 只对本次生效，不回写货品主数据 |
| 一配置三结果 | 同一处配置决定：是否生成加工单、作业端是否出现任务、是否产生计费事实 |

货主差异不产生第二条链路，也不出现按货主切换的单据状态机。

### 单据不产生费用，作业事实才产生

计费看事实流（见 08），不看单据状态。

直接后果：**单据取消不影响已发生事实的计费**。货已上架又被下架，仓储费照算，因为货确实占过库位。单据侧不做任何退款逻辑。

### 到货、上架、拣货这类进度怎么展示

不存状态，靠反推：

| 展示项 | 来源 |
|---|---|
| 到货进度 | 收货单已履约数量 ÷ 应收数量 |
| 上架进度 | 该收货单下未完成的上架任务数 |
| 拣货进度 | 波次与拣货任务组的完成比例 |

这些是查询时算出来的，不落字段，避免与任务表出现两份事实。

## 约束与验证

| 约束 | 强制手段 |
|---|---|
| 单据只有一个货主与一个仓 | 数据库层：`owner_id`、`warehouse_id` 非空；应用层：跨仓操作必须拆单 |
| 单据不改库存 | 代码层：单据模块不引用库存写入接口，ArchUnit 断言 AR-09（见 14） |
| 状态不得人工直改 | 应用层：状态变更只接受「受理、差异关闭、取消」三个命令；数据库层：状态无对外写接口 |
| 已完成必须满足数量 | 应用层：完成前校验任务片之和；核对层：日结比对汇总值与任务汇总 |
| 短量必须留痕 | 数据库层：差异关闭时差异量、原因、确认人三项非空 |
| 受理四校验不可绕过 | 应用层：受理接口内串联四校验，任一失败即回滚；不提供强制受理入口 |
| 单头不得加类型专有字段 | 构建期：单头实体字段变更需评审；类型专有字段只能进扩展表 |
| 单据不存波次 | 数据库层：单头无波次字段；波次成员关系在成员表（见 17） |
| 进度不落字段 | 构建期：单据表不得出现「进度」类字段；进度由查询算 |

引用的决策编号：D02、D21、D33、D41、D56、D57；不变量：INV-09、INV-10；模块归属见 03 M05，任务与波次见 06、17，算费见 08。

单据字段清单与表结构属 11，本文只定结构与规则。
